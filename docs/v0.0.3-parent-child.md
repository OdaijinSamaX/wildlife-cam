# v0.0.3 Parent-Child Architecture

## 目的

v0.0.3 では、データ取得を Raspberry Pi 5 から切り離し、以下の役割分担にします。

- 親機: Raspberry Pi 5
- 子機: Raspberry Pi Zero 2 W

責務:

- 子機: PIR 検知、録画、親機への動画転送
- 親機: クラウドアップロード、Web UI との接続

## データフロー

```text
Pi Zero 2 W (child)
  -> get_arm_state
  -> motion detected
  -> record clip
  -> upload_video over bluetooth
Pi 5 (parent)
  -> receive file
  -> WorkerUploader.upload()
  -> Cloudflare Worker
  -> R2 / Supabase
Web UI
  -> Supabase Auth
  -> Worker API
```

## 実行モード

`main.py` は `WILDLIFE_NODE_ROLE` で動作を切り替えます。

- `standalone`: 既存の単体運用
- `parent`: 親機
- `child`: 子機

## 必要な環境変数

### 親機

```env
WILDLIFE_NODE_ROLE=parent
WILDLIFE_LINK_TRANSPORT=bluetooth
WILDLIFE_API_URL=https://wildlife-cam-api.your-project.workers.dev
WILDLIFE_DEVICE_TOKEN=YOUR_DEVICE_API_KEY
WILDLIFE_LINK_PORT=4
```

サンプル: [config/.env.parent.example](C:/Users/iwhay/wildlife-cam-main/wildlife-cam-main/config/.env.parent.example)

### 子機

```env
WILDLIFE_NODE_ROLE=child
WILDLIFE_LINK_TRANSPORT=bluetooth
WILDLIFE_PARENT_BT_ADDR=B8:27:EB:12:34:56
TRAP_ID=YMK-001
WILDLIFE_API_URL=https://wildlife-cam-api.your-project.workers.dev
WILDLIFE_DEVICE_TOKEN=YOUR_DEVICE_API_KEY
WILDLIFE_LINK_PORT=4
```

サンプル: [config/.env.child.example](C:/Users/iwhay/wildlife-cam-main/wildlife-cam-main/config/.env.child.example)

共通の任意設定:

```env
WILDLIFE_LINK_SERVICE_UUID=5e0ec070-4ef1-4f8e-9c12-7b0ac8cb3a11
LOG_LEVEL=INFO
```

補足:

- `bluetooth` transport の `WILDLIFE_LINK_PORT` は TCP ポート番号ではなく RFCOMM チャネルです
- 1 から 30 の範囲にしてください。既定は `4` です
- `tcp` transport の場合だけ `8765` を使います
- 子機に `WILDLIFE_API_URL` と `WILDLIFE_DEVICE_TOKEN` を入れると、armed 状態は子機が直接 Worker API から取得します
- その場合、親機は動画の受信とアップロードだけを担当します

## 依存関係

Bluetooth リレーには `PyBluez` を使います。

```bash
sudo apt update
sudo apt install -y bluetooth bluez libbluetooth-dev ffmpeg
pip3 install python-dotenv requests pybluez2
```

子機は追加でカメラ・GPIO系が必要です。

```bash
sudo apt install -y python3-picamera2 python3-gpiozero
```

## 起動方法

### 親機

```bash
cd ~/wildlife-cam
python3 parent_main.py
```

親機は子機接続待ちになり、子機から渡された `trap_id` を使って armed 状態を確認します。

### 子機

```bash
cd ~/wildlife-cam
python3 child_main.py
```

子機は自分の `TRAP_ID` を親機へ渡しながら armed 状態を問い合わせ、PIR 待機します。

## 動作仕様

### armed 制御

- Web UI で `監視中` / `停止中` を切り替える
- 子機は既存の `GET /traps/:trap_id` で armed 状態を取得する
- 親機は armed 制御に関与せず、動画受信と upload に専念する
- `is_armed=false` の間、子機は録画も転送もしない

### 動画転送

- 子機は録画完了後、親機へ `upload_video` リクエストを送る
- 親機は受信ファイルを一時保存し、既存の `WorkerUploader.upload()` を実行する
- 成功時は親機・子機ともにローカル一時ファイルを削除する
- 失敗時は親機側に受信ファイルを残す

## ローカル検証

Bluetooth がない開発環境では、親機子機のリンク部分だけ `tcp` で確認できます。

### 親機

```env
WILDLIFE_NODE_ROLE=parent
WILDLIFE_LINK_TRANSPORT=tcp
WILDLIFE_PARENT_BIND_HOST=0.0.0.0
WILDLIFE_LINK_PORT=8765
```

### 子機

```env
WILDLIFE_NODE_ROLE=child
WILDLIFE_LINK_TRANSPORT=tcp
WILDLIFE_PARENT_HOST=127.0.0.1
WILDLIFE_LINK_PORT=8765
TRAP_ID=YMK-001
```

## 固定IPについて

Pi 5 が Wi-Fi と LTE を切り替えても同じ IP アドレスを保つことは、通常のローカルIP運用ではできません。今回の構成では親機からクラウドへ outbound で接続するだけなので、クラウドアップロード自体に固定IPは不要です。

固定の到達先が必要なのは次のケースです。

- 親機へ外部から直接 SSH したい
- 親機へ直接 Web や API を公開したい

その場合は別途、以下のどちらかで解決するのが現実的です。

- Tailscale のようなオーバーレイネットワーク
- 固定IP付き LTE / VPN / ルーター側の固定出口

今回はまだ親機へ外から直接入る仕様ではないため、v0.0.3 の必須要件には含めていません。
