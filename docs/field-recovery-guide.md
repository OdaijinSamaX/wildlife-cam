# 屋久島・カメラ実演の現地復旧手順

難しい操作は不要です。ノートPCからPiへ接続できたら、以下を上から順に行ってください。

## まず状態を見る

```bash
ssh wildlife-zero-ts '~/wildlife-cam/scripts/field-status.sh'
```

画面の `【NG】` を探します。すべて `【OK】` なら、そのまま待ってください。保存動画が「なし」でも、送信成功後はPiから削除されるため正常な場合があります。

## 「カメラサービス: 停止中」と出た

```bash
ssh wildlife-zero-ts '~/wildlife-cam/scripts/camera-restart.sh'
```

`【OK】カメラサービスは動作中です` と出たら、もう一度一発診断を実行します。

## ネットだけがNGになった

カメラは通信が戻るまで安全に待ちます。2～3分待ってから一発診断を再実行してください。ネット監視が自動復旧を試みます。

## 電池を交換する

電源ケーブルを抜く前に実行します。

```bash
ssh wildlife-zero-ts '~/wildlife-cam/scripts/safe-stop.sh'
```

`【OK】カメラは停止しました` と表示されてから電源を抜きます。交換後は電源をつなぎ、2～3分待って一発診断を実行してください。

## SSHで接続できない

1. 2～3分待って、もう一度だけ接続します。
2. それでも接続できなければ、電源を一度だけ抜き差しします。
3. 2～3分待ちます。連続で抜き差ししないでください。
4. もう一度一発診断を実行します。

## SDカード空きがNG、または再起動しても直らない

無理に録画を続けないでください。予備SDカードへ交換するか、詳しい人へ連絡してください。`read-only`、`I/O error`、`No space left` と表示された場合も同じです。

## 時刻が未同期と出た

画面の日時が正しければ短時間の実演は続けられます。日時が大きく違う場合は、ネットが戻って時刻同期が `【OK】` になるまで録画を始めないでください。

## 「送信保留(SDに待機中)」と出た

これは**異常ではありません**。LTE の通信費がかさまないよう、1 時間あたりの送信量に上限（既定 250MB）を設けています。上限に達すると**送信だけを一時的に止め、録画は続けて SD カードに貯めます**。時間の経過で送信予算が回復すると、貯まった分から自動で送信を再開します（画面に「◯◯時頃から順次送信再開」と出ます）。

- **録画は止まっていません。** 撮り逃しは起きません。貯まった動画は SD に残るので、あとで回収できます。
- 実演で「いま撮れた最新の映像」を見せたいときは心配いりません。バックログが多いときは**新しい動画から先に送る**設計です。
- WiFi につながっているときは上限は効きません（`送信量: WiFi 接続中のため上限なし` と表示）。
- すぐに全部送りたい場合は、WiFi のある場所に移動するか、詳しい人に送信上限（`WILDLIFE_UPLOAD_BUDGET_MB_PER_HOUR`）の一時引き上げを頼んでください。

## 出発前に一度だけ行う確認

1. 一発診断が表示できる。
2. カメラ再起動が `【OK】` になる。
3. 安全停止が `【OK】` になる。
4. Piの電源を入れ直し、2～3分後にserviceが動作中へ戻る。
5. PIRの前で動き、録画とupload成功をログで確認する。
