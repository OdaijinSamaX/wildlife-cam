# 設置候補地 電波調査プロトコル（屋久島・現地チェックリスト）

このページは**上から順に**実行すれば、その候補地に wildlife-cam を置いてよいか判定できます。
難しい操作は不要です。持ち物は **タッパー入りの Pi（wildlife-zero）とスマホ** だけで足ります。

> **スマホしか無いとき（推奨の動線）**
> 現地の操作は基本すべて母艦（自宅の Linux）経由の SSH で行います。スマホから
> **母艦の Windows Claude に「site-survey を候補地◯◯で流して」と頼めば、結果を読み上げてくれます。**
> 自分で打つ場合は下のコマンドをそのまま送ってください。

調査したい各候補地で **Pi に電源を入れ、2〜3分待って**（回線がつながるのを待つ）から始めます。

---

## 手順（各候補地で1回ずつ）

### ステップ 0. Pi に電源を入れ、2〜3分待つ

タッパーの Pi に電源をつなぎ、WiFi または LTE がつながるのを待ちます。

### ステップ 1. 電波調査を1発で流す

母艦から次の1行を実行します（`"候補地A"` は場所の名前に置き換え）:

```bash
ssh wildlife-zero-ts '~/wildlife-cam/scripts/site-survey.sh "候補地A"'
```

> スマホのみのときは、この1行を母艦の Windows Claude に頼んでください。

このスクリプトが **WiFi電波 → LTE電波 → インターネット疎通 → 実サイズ相当のアップロード実測（約1分）**
を続けて測り、最後に**総合判定**と**記録用の1行**を出します。全体で約1分で終わります。

画面はこう出ます（例）:

```text
■ 1. WiFi 電波
   => 最強: MyHomeWiFi  電波 78%  【OK】（既設WiFi至近とみなせる）
■ 2. LTE 電波
   LTE 電波: 61%  (lte, povo2.0)  【OK】
■ 3. インターネット疎通
   【OK】 オンライン（名前解決・外部到達ともに成功）
■ 4. アップロード実測（3MB を送って速度を測る）
   実測: 5.20 Mbps  （3.0MB を 4.8s で送信, HTTP 200）
■ 総合判定
   【OK】 【最小BOM可】既設WiFi至近。¥1〜2万円台の最小構成で設置可。
■ 記録用（スマホに控える1行）
   候補地=候補地A / WiFi=MyHomeWiFi(78%) / LTE=61% / オンライン=OK / 上り=5.20Mbps
```

### ステップ 2. 「記録用の1行」をスマホに控える

最終行の `候補地=… / WiFi=… / LTE=… / オンライン=… / 上り=…Mbps` を、下の**記録テンプレ**に写します。
座標（緯度経度）はスマホの地図アプリで長押しして取得します（スクリプトは座標を測りません）。

### ステップ 3. 総合判定を読む

`■ 総合判定` の1行がそのまま結論です。判定の意味は次の「判定マトリクス」を参照。

### ステップ 4. 次の候補地へ

Pi を次の場所へ移し、ステップ0からやり直します。

---

## 判定マトリクス

スクリプトの `■ 総合判定` は下の表の自動判定です。手動で見直すときの基準も同じです。

| 状況 | 目安 | 判定 | 意味・注意 |
|---|---|---|---|
| **既設WiFi至近** | WiFi 電波 **55%以上** かつ オンラインOK | 🟢 **最小BOM可** | ¥1〜2万円台の最小構成で設置可。WiFi 接続時は**送信量の上限なし**（LTE 課金の心配なし）。まず WiFi へ接続設定する。 |
| **LTE単独** | WiFi 弱い／無し・オンラインOK・LTE 電波 20%以上・上り **0.5Mbps以上** | 🟡 **LTE単独（要注意）** | 運用可だが**従量課金に注意**。送信量上限は既定 **250MB/時**（夜間12hで最大約3GB）。詳細は `docs/upload-budget.md` と `field_limits.py`。上限は `WILDLIFE_UPLOAD_BUDGET_MB_PER_HOUR` で調整可。 |
| **両方弱い** | 上記のどちらも満たさない（オフライン／上り 0.5Mbps 未満 等） | 🔴 **設置不可** | WiFi も LTE も実用に足りない。**別の候補地へ。** 数十cm〜数m 動かす／地上高を上げる／窓・開けた方角へ向けると改善することがある。 |

**なぜ 0.5Mbps が境目か**: LTE の送信量上限 250MB/時 をちょうど送り切るのに約 0.58Mbps 必要。
これを下回ると SD に貯まる一方になり、実演で「今の映像」を見せにくくなります。2Mbps 以上あれば余裕です。

## 困ったとき

- **`【NG】 WiFi が 1 つも見えません` / `LTE モデムが見つかりません`**
  Pi が起動しきっていない可能性。2〜3分待って**もう一度**流す。連続で電源を抜き差ししない。
- **`【NG】 オフライン`**
  その場所は WiFi も LTE も外に出られていません。数m 動かすか、`docs/field-recovery-guide.md` の復旧手順を試す。
- **アップロードが `送信失敗/時間切れ`**
  回線が非常に細いか不安定。上り 0.5Mbps 未満と同じ扱い（実質「設置不可」寄り）で判断。
- **SSH で Pi に入れない**
  `docs/field-recovery-guide.md`「SSHで接続できない」を参照。まず 2〜3分待って再試行。

## 参考（上級者向け・省略可）

スクリプトは環境変数で調整できます（既定のままで問題ありません）。

| 環境変数 | 既定 | 説明 |
|---|---|---|
| `SURVEY_UPLOAD_MB` | `3` | アップロード試験のサイズ MB（実クリップ約1本ぶん）。 |
| `SURVEY_UPLOAD_URL` | 公開の速度計測サーバ | 送信先。**秘密情報なし**。実運用の送信先で測りたいとき差し替え可。 |
| `SURVEY_TIMEOUT` | `45` | アップロードの打ち切り秒数（全体を約1分に収める）。 |

例（送信サイズを 5MB にして測る）:

```bash
ssh wildlife-zero-ts 'SURVEY_UPLOAD_MB=5 ~/wildlife-cam/scripts/site-survey.sh "候補地A"'
```
