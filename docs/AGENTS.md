# enclosure-lab で AI が設計するときの規約

このファイルが設計スクリプトの正本。`designs/` に置くファイルは必ずこの形にする。
上位のプロトコルは `/srv/homelab/repos/home-lab-setup/AGENTS.md` にある。矛盾したら
安全側（厳しい方）を採る。

## 0. 大原則

- **AI には目が無い。** 書いた形が正しいかは、レンダと数値チェックを通してしか
  分からない。設計を書いたら必ず `uv run python -m harness check` を通し、
  `out/<design>/report.md` の画像と数値を見てから次に進む。
- **推測を数字として書かない。** 分からない寸法は決め打ちせず「推定」と明記する。
- **チェックが PASS したことは、設計が正しいことを意味しない。**
  各チェックの「限界」（`docs/HARNESS.md`）に書いてあるものは見逃す。

## 1. ファイルの形

```python
"""何のための部品か / 想定する取り付け方 / 未確定事項"""

import cadquery as cq
from parts import hcsr501

DESIGN_NAME = "pir_bezel"          # 省略するとファイル名が使われる

PARAMS = {                          # 全ての寸法はここに集約する
    "wall": 3.0,

}

PRINT_ORIENTATION = {"rotate": (180, 0, 0)}   # 造形姿勢。overhang はこれを適用してから見る

COMPONENTS = [hcsr501.place(at=(0, 0, -6.2))] # 内蔵部品。clearance / interference に使う

CHECK_CONFIG = {
    "min_wall_mm": 1.6,
    "max_bbox_mm": (256, 256, 256),
    "max_overhang_deg": 50,
    "component_clearance_mm": 0.4,
}

SECTIONS = [                        # 任意。省略すると XZ 中央 / YZ 中央
    {"name": "xz_mid", "origin": (0, 0, 0), "normal": (0, -1, 0)},
]

def features(p=PARAMS):
    """各フィーチャの占有領域 (claim) を返す。layout チェックが突き合わせる"""

def build(p=PARAMS):
    """cq.Workplane か cq.Assembly を返す"""
```

## 2. 座標と単位

- 単位は **mm**、**Z が上**。
- 原点は **「取り付け基準面」** に置く。壁を貫通する部品なら「筐体壁の外面」、
  基板を載せる部品なら「基板の座面」。docstring に必ず書く。
- 造形姿勢は `PRINT_ORIENTATION` で表す。設計座標を造形の都合で歪めない。

## 3. 寸法の書き方

**式の中に生の数値を置かない。** すべて `PARAMS` に出し、各行に出所を書く。
出所は次の 3 種類だけを使う。

| 書き方 | 意味 |
|---|---|
| `# HC-SR501 データシート` | 一次資料に載っている値 |
| `# 実測 2026-08-22` | ノギスで測った値。日付を必ず書く |
| `# 推定（未実測）` | 根拠のない概算。**必ず「推定」と書く** |

`PARAMS` に書くのは常に **狙い寸法**（印刷後にこうなってほしい寸法）。
造形の癖を吸収する補正は §3.5 のテーブルが当てる。

計算で出した値は `# 計算値: 23.0 + 2 * (1.5 * 0.75)` のように式ごと残す。
設計方針で決めた値は `# 設計値` と書く。

推定値は後で実測に差し替える。差し替えたら:

1. `PARAMS` の値とコメントを更新する
2. 部品側なら `parts/*.py` の `DIM_SOURCE` を `"measured:YYYY-MM-DD"` に変える
3. **その部品を使っている全ての設計で `harness check` を回し直す**

## 3.5 寸法補正テーブルを通す（`FIT_TABLE`）

**設計スクリプトには「印刷後にこうなってほしい寸法（狙い寸法）」を書く。**
図面寸法への変換は `harness/fit.py` の補正テーブルが一箇所でまとめて行う。

```python
from harness import fit

FIT_TABLE = fit.ASA_P1S        # どのテーブルで刷るかを宣言する（必須）

PARAMS = {
    "shaft_dia": 10.1,          # 狙い寸法。図面には 10.4 が描かれる
    "pin_dia": 10.0,            # 狙い寸法。図面には 10.25
    "wall": 1.6,                # 狙い寸法。図面も 1.6（補正不要）
}

def build(p=PARAMS):
    f = FIT_TABLE
    cq.Workplane("XY").circle(f.hole(p["shaft_dia"]) / 2)     # 内径
    cq.Workplane("XY").circle(f.boss(p["pin_dia"]) / 2)       # 外形の突起
    ... f.wall(p["wall"]) ...                                  # 肉厚
```

**規約:**

- **`FIT_TABLE` の宣言は必須。** 無いと `fit` チェックが FAIL する。
  意図して補正しない場合も `FIT_TABLE = fit.NONE` と明示すること
  （「測り忘れ」と「意図した無補正」を区別するため）。
- **設計者が式の中で `+ 0.3` などと足し引きしてはいけない。**
  マジックナンバーを散らすと、材料を変えたときに全部を追えなくなる。
- 根拠が無い種類の寸法は `f.uncompensated(値, "理由")` で通す。
  黙って素通しするのではなく、report に「無補正」として記録される。
- テーブルに規則が無い寸法帯は自動で隣から外挿され、report に「外挿」と出る。
  外挿が気になるなら、その帯を測るフィーチャをクーポンに足すこと。

**ハーネスは `build()` を 2 回評価する。** 設計側は意識しなくてよい。

| モード | `hole(10.1)` | 使い道 |
|---|---|---|
| `target` | 10.1 | **全てのチェックとレンダ**。印刷後の形を検証したいので |
| `print` | 10.4 | **STL / 3MF の書き出し**。スライサに渡す形 |

STEP は狙い形状、STL と 3MF は補正済み形状。`report.md` の `fit` セクションに
「どのテーブルで、どの寸法にいくら足したか」が全部出るので、必ず目を通すこと。

補正値は **材料・機種・ノズル径・造形姿勢** の組にしか意味がない。
別材料に移るときの手順は `designs/wildlife_cam/fit_coupon.md` の 5 章。

## 4. parts/ の使い方

内蔵部品（プリントしない実物）は `parts/` のモジュールを使う。各モジュールは:

```python
DIM_SOURCE = "datasheet" | "measured:YYYY-MM-DD" | "estimated"
def model(**kw) -> cq.Workplane            # 実体
def envelope(clearance=0.0, **kw) -> cq.Workplane   # 外形 + クリアランス
ENVELOPE = envelope(0.5)
def place(at=(0,0,0), rotate=(0,0,0), **kw) -> Component  # 配置済み
```

`COMPONENTS` には `place()` の戻り値を入れる。生の `Workplane` を入れても動くが、
その場合 envelope がバウンディングボックス近似になり、レポートに警告が出る。

**envelope は「意図した接触面」にはクリアランスを足さない。**
たとえば基板を端面で押さえる構成なら、その面は接触が正しいのでクリアランス 0 にする。
足してしまうと、正しい設計が clearance FAIL になる。

### 内蔵部品の寸法順位（2026-08-22 時点）

筐体の内寸は**最長の部品**で決まる。設計を始める前にこの表を見ること。

| 部品 | 最大寸法 | 剛体か | 備考 |
|---|---|---|---|
| **OTG ケーブル** | **150.0 mm** | 可動 84.2 / 剛体 65.8 | micro-USB オス - USB-A メス。折り返せるのは可動部だけ |
| **SORACOM Onyx (SC-QGLC4-C1)** | **95.0 mm** | 剛体 | **剛体では最長。** USB-A プラグ直付けのドングルで、抜き差し代を含めると 110 mm 前後の直線的な空きが要る。外部アンテナ (CRC9 x 2) の位置が未確定なので、いまは長辺の両側に 27 mm ずつ逃げを取ってある |
| Pi Zero 2 W | 65.0 mm | 剛体 | 実装部品高さとコネクタ抜き差し代は推定 |
| 850 nm IR 投光器 | 45.0 mm | 剛体 | 推定寸法。発熱するので外気に面させるか放熱経路を別に設計する |
| HC-SR501 PIR | 32.8 mm | 剛体 | 実測 2026-08-22。ツバが無いので接着封止キャリアで扱う |
| Camera Module 3 NoIR | 25.0 mm | 剛体 | レンズ鏡筒は推定 |

**Onyx を寝かせて入れられる箱でなければ、そもそも構成が成立しない。**
Pi Zero 2 W (65 mm) を基準に箱を決めると必ず入らなくなる。

熱の律速も Onyx で、動作温度の上限が **+60 degC**。直射日光下の黒い密閉筐体は
容易にこれを超える。日射と放熱の扱いは筐体設計側で解くこと（`parts/` のダミーは
発熱も放熱も一切表現していない）。

### 直列に並べると造形枠を超える（折り返し配置が必須）

```
Pi Zero 2 W   65.0
OTG ケーブル 150.0
SORACOM Onyx  95.0
--------------------
合計         310.0 mm   >   P1S の枠 256 mm
```

**直線配置は成立しない。** 折り返せるのは OTG ケーブルの可動部 84.2 mm だけで、
両端のコネクタ 65.8 mm は曲げられない剛体。`parts/otg_cable.folded_span(legs)`
で目安が出る（2 本折りで 92.9 mm、3 本折りで 73.9 mm）。
折り返しには最小曲げ半径 15 mm（推定）ぶんの逃げも要る。

## 4.5 フィーチャの占有領域を宣言する（`features(p)`）

`interference` は **別ソリッド同士**しか見ない。`openings` は溝を止まり穴としか
見ない。そのため「1 個のソリッドの中でフィーチャが場所を奪い合っている」状態を
拾う手段が無い。実際に fit_coupon 初版では、O リング溝の帯が基準ピン φ10.0 の
根元を 0.95 mm 削っていたが、どのチェックにも掛からなかった。

そこで設計側が占有領域を宣言し、`layout` チェックが総当たりで突き合わせる。

```python
from harness import feature

def features(p=PARAMS):
    m = p["feature_margin"]          # 既定は min_wall / 2
    t = p["plate_t"]
    return [
        # 貫通穴: 板厚いっぱい
        feature.cylinder("clear_3.2", (x, y), 3.2, 0.0, t, margin=m),
        # 止まり穴: 空洞 + その下に残すべき肉
        feature.cylinder("heatset_4.2", (x, y), 4.2, t - 6.0 - 1.6, t, margin=m),
        # 台座から立つピン: 足元の板を厚み方向いっぱいまで
        feature.cylinder("ref_pin", (x, y), 10.0, 0.0, t + 12.0, margin=m),
        # 溝: 環として。バウンディングボックスで包むと内側の land まで占有してしまう
        feature.ring("oring_groove", (cx, cy), 30.0, 2.70, t - 1.5 - 1.6, t, margin=m),
        # 刻印など形が複雑なもの: 実体のバウンディングボックスから
        feature.from_shape("label_title", text_shape, margin=m, z0=t - 0.6, z1=t),
    ]
```

**規約（ここを外すと検出できない）:**

- **claim は「フィーチャ自身の体積」ではなく「そのフィーチャが所有すべき材料領域」。**
  台座から立つピンは足元の板を厚み方向いっぱいまで claim する。ピン (z=8..20) と
  溝 (z=6.5..8) は体積が重ならないので、自分の体積だけを claim すると
  今回の不具合をそのまま取り逃がす。
- 止まり穴は空洞 + その下に残す肉（min_wall）まで。
- マージンの既定は `min_wall / 2`。2 つの claim が重なった時点で、フィーチャ間に
  残る材料が min_wall を下回っている、という意味になる。マージンは横方向にだけ効く。
- 同軸に積み上がっていて**接するのが正しい**フィーチャ（座ぐり / 内径の溝 / 面取り）は、
  ひとつの claim にまとめる。別々に宣言すると意図した連続を誤検出する。
- `build()` と `features()` は **必ず同じ PARAMS・同じ位置関数** から組み立てる。
  座標をベタ書きで二重に持つと、いずれ宣言と実物がずれて検出できなくなる。

穴（B-rep の内向き円筒面）は、どの claim にも入っていなければ
「宣言し忘れ」として FAIL になる。ボスや刻印の宣言し忘れは検出できないので、
フィーチャを足したら claim も足すこと。

## 4.9 現地で保守する人のための設計原則（**全設計に適用**）

**現地でこの機材を保守するのは、機械に強くない人である。設計者本人ではない。**
現地は暗く、寒く、手袋をしていて、説明書は無く、落とした部品は落ち葉の中で
二度と見つからない。この前提は wildlife-cam に限らず box-trap-sensor など
**現場に置く装置すべてに共通**するので、一般原則としてここに書く。

### 4.9.1 原則

1. **落とすと失う。** ねじ・ワッシャは**脱落しない捕捉式**にする。
   蓋を開けたときにねじが蓋側に残る構造（E リング / 段付きねじ / 蓋側の
   圧入ワッシャ）にする。現地でばらばらになる部品を作らない。
2. **数を減らして大きくする。** 小さいねじ 8 本より**大きいねじ 3 本**。
   手袋をした手で扱いやすく、紛失も減る。締結点が減るぶん 1 点あたりの
   面圧は上がるので、パッキンの潰し量は再計算すること。
3. **向きを間違えられない形にする（ポカヨケ）。** 誤った向きでは物理的に
   嵌まらないようにする。ねじ位置を非等分にする、キー溝を片側だけ付ける、
   コネクタ側に段差を付ける。**蓋・ドーム・内部の基板すべてに適用する。**
4. **パッキンが座ったか目で見て分かるようにする。** 閉じると見えない構造を
   避ける。合わせ面に段差を設け、浮いていれば隙間が見えるようにする。
   「締めたつもり」を現地で検出できることが重要。
5. **刻印で現地に情報を残す。** 現地に説明書は無い。
   **開ける向き・締める順序・上下・型番・製造年月**を筐体自体に彫る。
   刻印の線幅は 0.8 mm 以上（`fit_coupon` の実測で size 4 の文字は 0.28 mm に
   なり印刷できなかった。size 6 以上にすること）。
6. **工具なしを優先する。** ただし**防水にはパッキンを潰す力が必要**なので、
   締結力は弱くできない。**力は掛かるが道具は要らない**方式を選ぶ（§4.9.2）。
7. **手順を書き、手順が原則を満たしているか点検する。** `docs/field-procedure.md`。

### 4.9.2 締結方式の比較（力は要る・道具は要らない）

| 方式 | 締結力 | 工具 | 捕捉 | ポカヨケ | 印刷適性 | 評価 |
|---|---|---|---|---|---|---|
| 通常のねじ（六角穴） | **高い** | **要る** | しにくい | 位置で可 | インサートで可 | 現地では最後の手段 |
| **蝶ねじ** | 中〜高 | **不要** | E リングで可 | 位置で可 | インサート + 市販蝶ねじ | **本命** |
| **ローレットねじ** | 中 | 不要 | 同上 | 同上 | 同上 | 蝶ねじより力が入りにくい |
| **トグルラッチ**（市販） | **高い** | 不要 | 本体に固定 | 形状で可 | 取付座を印刷 | **大きな蓋に本命** |
| 印刷した爪（スナップ） | **低い** | 不要 | 一体 | 形状で可 | 可 | **パッキンを潰すには不足** |
| 嵌合（ドーム蓋など） | 低〜中 | 不要 | 既製品 | 形状で可 | 受けを印刷 | 保持専用。防水は O リングに任せる |

**選び方:**

- **パッキンを潰す合わせ面 -> 蝶ねじ か トグルラッチ。** 爪では面圧が足りない。
- **保持だけでよい所 -> 嵌合 or 爪。** 例: ドーム蓋。
- ねじを使うなら**大きく・少なく・捕捉式**（原則 1・2）。

### 4.9.3 スライド嵌合を優先する

**部品の固定はできるだけねじではなくスライド嵌合にする。**
レール・アリ溝・T スロット・差し込みで「スッと嵌める」形を優先し、ねじは
必要な箇所にだけ使う。現地の人が扱いやすく、ねじの紛失も減る。

ただし工学的な注意を必ず織り込むこと。

1. **スライドだけでは振動で抜ける。** 設置先は細い木で、風で揺れ続ける。
   数ヶ月かけて少しずつ動いて外れうる。
   **位置決めはスライド、抜け止めは別に最小限**、という役割分担にする。
   爪によるクリック止めなら工具ゼロを維持できる。ねじを使うなら **1 本**で足りる形にする。
2. **摺動面の造形方向。** 摺動面が積層の段差を横切ると引っかかる。
   **段差が摺動方向と平行に走る姿勢**にし、`PRINT_ORIENTATION` で宣言して
   根拠を書くこと。アリ溝はフランクを 45 度以下にすればサポートが要らない。
3. **丸穴で取った補正値は角形状に効く保証が無い。**
   いまの補正（穴 +0.30 / 突起 +0.25）は丸穴と丸棒で取った値である。
   レール・アリ溝には別の値が要りうるので、`fit_coupon_v2` に
   **隙間 +0.2 / +0.3 / +0.4 / +0.5 のアリ溝試験**を入れてある。
   実測が出るまで、スライド嵌合の寸法は暫定として扱うこと。
4. **スライドで代替できない所を見極める。**
   **パッキンを潰して防水する合わせ面は面圧が要るので、スライドでは代替できない。**
   そこはねじかラッチが必要。この線引きを設計ごとに明記すること。

### 4.9.4 スライドで防水も兼ねられるか（摺動シール）

スライド嵌合にパッキンを噛ませて防水も同時に成立させたい場合、
**成立する形と成立しない形がはっきり分かれる。**

| 形 | 成立するか | 理由 |
|---|---|---|
| **ピストン式**（半径方向で締める） | **成立する** | 差し込む部品の周囲の O リングが、受け側の内壁との間で**半径方向に潰れる**。挿入の最後だけ潰れ、摺動距離が短い。`pir_bezel` で採用済みの原理の横展開 |
| **引き出し式**（面を擦って締める） | **成立しない** | パッキンが面の上を摺動して毎回摩耗し、溝から転がり出る。**数回で漏れ始める** |

**ピストン式を成立させる 3 条件**（設計に必ず入れること）。

1. **造形方向。** 摺動シール面の積層段差が**摺動方向（軸方向）に走っていると、
   それがそのまま漏水経路になる。** 段差が O リングと平行（＝周方向）に走る姿勢に
   すること。つまり**軸を造形方向に平行**にする。`PRINT_ORIENTATION` で宣言し、
   根拠を書く（`pir_bezel` と `window_snoot` が実例）。
2. **挿し口の面取り。** 角のまま押し込むと **O リングが切断される。**
   切れても外からは見えず、浸水するまで気づけない。
   **リードインの面取りまたは R を必ず設ける**（15〜30 度 x 1 mm 以上）。
3. **シリコングリスの塗布を運用手順に含める。** 摩耗が減り、印刷面の粗さも埋まる。
   `docs/field-procedure.md` に書く。

### 4.9.5 ベイパースムージング（採用判断は保留・記録のみ）

ASA はスチレン系なので**アセトンによるベイパースムージングが効く**。
層の隙間が封じられるので、**摺動シール面の品質が上がり、摩耗も漏れも減る。**

ただし採用するなら次を織り込む必要がある。

- **寸法が変化する。** 今回実測した補正テーブル（穴 +0.30 / 突起 +0.25）の**上に
  さらに補正が要る**。適用するなら**嵌合部とインサート下穴を再校正**すること
  （`fit_coupon` を平滑化した状態で刷り直して測る）。
- **引火性が高い。** 容器は PP 製が必要。換気必須。

**今すぐ採用する判断ではない。** 摺動シールを採る場合に価値が上がる選択肢として
記録しておく。

## 5. 造形の前提（P1S / ASA / 0.4 mm ノズル）

| 項目 | 既定値 | 根拠 |
|---|---|---|
| 最小肉厚 | 1.6 mm | 0.4 mm 押出幅 x 4（外壁 2 + 内壁 2）。屋外品で割れない下限 |
| 造形枠 | 256 x 256 x 256 mm | P1S のビルドボリューム |
| オーバーハング閾値 | 50 度 | ASA でサポート無しに刷れる限界のあたり |
| 層厚 | 0.2 mm | 第 1 層の判定に使う |
| ブリッジ可の渡り幅 | 10 mm | これを超える下向き面はサポートが要るとみなす |

意図的にこれを外す設計（例: 公差クーポンの 0.8 mm 薄板）は、`CHECK_CONFIG` で
閾値を上書きし、**なぜ外すのかを docstring に書く**。黙って外さない。

## 6. 防水設計のルール

- **開口は必ず `CHECK_CONFIG["expected_openings"]` に宣言する。**
  宣言が無いと openings チェックは WARN のまま素通りする。宣言してあれば、
  意図しない貫通穴が増えた瞬間に FAIL になる。
- ねじ穴を O リング溝の内側に置かない。置いたらそこが漏れ経路になる。
  外側に置いた場合は「相手側のボスを止まり穴にする」ことを docstring に書く。
- 密閉筐体には通気ベント（`parts/gore_vent.py`）を入れる。内圧の振れを逃がさないと
  O リングを押し広げて水を吸う。
- O リング溝の寸法は `parts/oring.py` の根拠（圧縮率 25% / 充填率 78%）に従う。
  外すなら計算し直して docstring に残す。
- PIR は遠赤外を見るので、アクリルや PC の窓を透過しない。窓を張る構成は成立しない。
  さらに HC-SR501 のドームには **O リングを座らせるツバが無い**（実測 2026-08-22:
  FLANGE_DIA == DOME_DIA == 23.0）。「フランジを押し付けて封止する」構成は不成立。
  採用した接着封止キャリアと、不採用にした案の根拠は [DECISIONS.md](DECISIONS.md) の D-001。
- **不採用にした案は `docs/DECISIONS.md` に残す。** 同じ検討を二度やらないため。

## 7. 書いたあとにやること

```bash
uv run python -m harness check designs/<...>.py
```

1. `report.md` の **断面図を必ず見る**。防水筐体は溝と肉厚が中に隠れるので、
   外観だけでは判断できない。
2. FAIL/WARN の実測値を読む。閾値を緩める前に、まず形を直せないかを考える。
3. 新しい種類の失敗を潰したら、`tests/test_checks_negative.py` にその失敗を
   再現するケースを足す。**ネガティブテストが無いチェックは未完成。**
   既存のチェックに掛からない不具合が出たら、まずチェックを足すことを考える。
4. 推定値のまま残っているものを docstring の「未確定事項」に列挙する。

## 8. やってはいけないこと

- チェックを通すためだけに閾値を緩める（理由を書かずに）
- 現地で落としたら失う部品を作る（§4.9）
- パッキンを潰す合わせ面をスナップ爪だけで締める（面圧が足りない・§4.9.2）
- 造形の癖を吸収するために式の中で寸法を足し引きする（§3.5 のテーブルを使う）
- `FIT_TABLE` を宣言しないまま設計を書く
- 推定寸法を「実測」と書く
- `out/` をコミットする
- 実測が入っていない部品の設計を印刷に回す
