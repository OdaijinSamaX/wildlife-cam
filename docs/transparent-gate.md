# 透明送信ゲート (Transparent Transmission Gate)

wildlife-cam が録画した動画のうち「野生動物が写っている可能性のあるもの」だけを
LTE で送信し、それ以外を現地の SD カードに保管する仕組み。

## なぜ学習モデルを使わないか

送信ゲートは**データの運命を決める唯一の場所**である。ここがブラックボックス
(学習済みニューラルネットワーク等) だと:

- どの動画が「送られなかったか」の理由を数値で説明できない
- モデルの更新でデータセットの検出特性が黙って変わる
- 検出確率 (detection probability) を定量化できず、在不在解析・密度推定の
  前提が崩れる

そこで本システムは判定を 2 段に分離する:

| 段 | 役割 | 実装 | データの運命 |
|---|---|---|---|
| 第1段 (Pi・本書) | 送信/保管の判定 | 決定論ルール | **決める** |
| 第2段 (homelab) | 種の同定ラベル | 任意 (LLM/人間/モデル) | 決めない (事後・上書き可) |

第 2 段は送信済み動画への注釈にすぎず、やり直しがきく。よって第 1 段さえ
透明であれば、データセット全体の追跡可能性が保たれる。

## 第1段の機序 (motion_screen.py)

1. **デコード**: ffmpeg で 320x176 グレイスケール・2fps に落とす
2. **差分**: 隣接フレームの輝度差が `pixel_delta` 以上の画素を「変化」とする
3. **ブロック化**: 8x8 画素ブロック (40x22=880 個) 単位で集計しノイズ粒を除去
4. **ブロブ**: 最大連結成分の面積 (%) と重心を毎フレーム記録
5. **特徴量** (すべて judgment.json に生値で記録):
   - `max_blob_pct` — 最大動体の画面占有率
   - `active_seconds` — 実質的な動体が観測された秒数
   - `net_travel_pct` — **正味移動**: 軌跡の前半1/4平均位置から後半1/4平均位置
     までの距離 (画面幅%)。往復運動は始点に戻るため伸びない
   - `max_excursion_pct` — 軌跡上の任意2点間の最大距離 (画面幅%)。判定には
     使わず記録のみ。`max_excursion >> net_travel` はその場での往復の署名で、
     held/ 回収後の閾値較正に使う
6. **判定表** (閾値は `config/screen_rules_v1.json`・バージョン管理):

```
1. 変化ブロックが皆無 (max_blob_blocks == 0)                 → none (無変化)
2. 面積が動物帯 AND 持続≥min AND 正味移動≥min                → wildlife (送信)
3. 正味移動が微小 (<veg_travel_max) AND 面積が動物帯未満     → none (植生の揺れ)
4. それ以外                                                  → uncertain (送信)
   解析失敗                                                  → error (送信)
```

「動物は横切る・植生はその場で揺れる」が分離の物理的根拠。正味移動
(net travel) は往復運動では伸びないため、風で揺れる下草と移動する動物を
学習なしで分離できる。

**測り方が本質**: 正味移動を「軌跡上の任意2点間の最大距離」で測ってはいけない。
フレーム差分のブロブ重心は物体の前縁と後縁を交互に立てるため、その場で
揺れるだけでも物体の幅ぶんの値が出る。合成クリップでの実測では、大きく揺れる
箱の「最大2点間距離」は 10.0% に達し、ゆっくり横切る動物 (15.8%) と分離できない。
始点→終点の変位で測れば 2.5% vs 11.7% となり分離できる。

**none を出す口は 1 と 3 だけ**で、どちらも積極的な事実に基づく (1=何も変化して
いない、3=その場で揺れる小さいもの)。閾値に届かない弱い動体は none ではなく
uncertain (送信) に落ちる。「証拠が無いこと」を「動物が居ないこと」の根拠に
しないための構造で、偽陰性をデータに焼き付けない生命線にあたる。

## 追跡可能性の担保 (3点セット)

1. **判定式が人間可読** — 上の表と JSON の閾値がすべて。紙に書ける
2. **全クリップに judgment.json** — 特徴量の生値・各ルールの評価 (値/閾値/合否)・
   ルール版・判定・処理時刻。「なぜ送られなかったか」に必ず数値で答えられる
3. **不送信の動画も削除しない** — `videos/held/` に保管し自動削除から除外。
   SD 回収後に全量を再解析でき、**偽陰性率を実測できる** (= 検出確率を論文に書ける)

## 運用パラメータ

| 設定 | 既定 | 意味 |
|---|---|---|
| `WILDLIFE_SCREEN_ENABLED` | 0 | 1 でゲート有効。無効時は従来どおり全量送信 |
| `WILDLIFE_SCREEN_RULES` | config/screen_rules_v1.json | 閾値セット (版管理) |
| `WILDLIFE_STORAGE_NOTIFY_PCT` | 80 | SD使用率がこの%で回収要請を Telegram 通知 |
| `WILDLIFE_STORAGE_STOP_PCT` | 95 | この%で録画停止 (データ保全を録画継続より優先・ユーザー決定) |

判定に迷う場合・解析に失敗した場合は必ず送信に倒す (偽陰性をデータに焼き付け
ない)。閾値を変えるときは新しい版ファイル (`screen_rules_v2.json`...) を作る。
どの動画がどの版で判定されたかは judgment.json で常に追跡できる。

## 較正と検証の手順

- 導入初期はゲート有効のまま **held/ も定期回収して全数レビュー**し、
  偽陰性 (動物が写っているのに保管された動画) を数える
- 偽陰性が出たら、その judgment.json の特徴量を見て閾値を調整し、新版として発行
- 夜間 IR / 昼間で特徴量分布が変わるため、両条件のサンプルで確認する

## 第2段 (種同定) の記録規約

送信済み動画への種ラベルは videos テーブルの `species` / `confidence` /
`analysis_status` に書く。ラベル付与の主体と方法 (`homelab-batch/<手法名>@<版>`
/ `human/<誰>`) を必ず記録し、人間の承認で確定する。第 2 段の手法変更は
データ選別に影響しないため自由に改善してよい。
