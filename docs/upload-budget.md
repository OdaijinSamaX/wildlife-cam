# 送信量上限（LTE 従量課金対策）— 設計と判断

## 背景

8/6 のネット障害を直した結果、次のボトルネックが露出した。実地テスト（LTE 単独稼働）で
**23 分で 271MB** を送っていた。枝や熱源への PIR 誤検知で 20〜30 秒おきにフル画質動画を
送り続けたのが原因。povo は従量課金なので、このままでは屋久島で通信費が破綻する。

## 方針（本人決定）

**撮影は絞らない。「送信量」だけに上限をかけ、超えた分は SD に貯める。**
狙いは「撮り逃しを作らない」こと（本来の目的＝網罠に入ったタヌキを数える）。
検知は全部拾い、外に出す量だけを絞る。

- 夜間 12 時間 × 250MB/時 = 最大 3GB/夜 に収まる見込み。

## 実装（`field_limits.py` / `runtime.py` / `video_storage.py`）

### 送信量の上限（本体）

- `WILDLIFE_UPLOAD_BUDGET_MB_PER_HOUR`（既定 **250**）。
- **ローリング 1 時間ウィンドウ**で、実際に送信したバイト数を積算する。上限に達したら
  **アップロードのみ停止**し、録画は続けて SD に貯める。予算が回復し次第、順次送信を再開する。
- **LTE のときだけカウント**（default route が `wwan0` か。`scripts/net-status.sh` と同じ規則）。
  WiFi のときは無制限。
- 送信履歴（時刻・バイト数）は永続化（既定 `/var/lib/wildlife-cam/uploads`）。**再起動でリセットされない。**

**ウィンドウ方式＝ローリングを採用した理由**: 「毎時 0 分リセット」の固定窓は、リセット直後に
バースト送信が起きて実効レートが上振れする。ローリング窓は「直近 60 分の実送信量」を素直に
上限化でき、実装も送信イベントを窓内で合計するだけで軽い。よってローリングを選んだ。

### 送信順序（★重要）

予算超過でバックログが溜まると、古い順のままでは「いま撮れた最新の動画」が何時間も後回しに
なり、実演で「目の前で撮れたものが届く」体験が壊れる。

**採用した規則**:
1. 新しく録画した 1 本は、その場で（予算があれば）**即送信**する（`runtime.py` の録画直後の送信経路）。
   → 予算に余裕があれば、最新の 1 本は常に最初に届く。
2. SD に溜まったバックログを送る `drain` は、**本数が閾値
   `WILDLIFE_UPLOAD_NEWEST_FIRST_BACKLOG`（既定 10）以下なら古い順**（時系列で自然に消化）、
   **閾値を超えたら新しい順**に切り替える。

**この規則を選んだ理由**: 通常時（バックログ小）は古い順で時系列どおり消化するのが素直。
誤検知で山が膨れたとき（バックログ大）は、実演価値の高い最新を優先して届け、古い山は SD に
残して現地回収に回す。「常に新しい順」だと平常時に時系列が乱れ、「常に古い順」だと実演で最新が
埋もれる。閾値切り替えが両者の良いとこ取りになる。

送れずに残った古い動画は **SD に残す。勝手に捨てない**（現地回収前提）。

### SD 容量との整合（事故を作らない）

撮影を絞らなくなり SD へ貯まる速度が上がった（誤検知環境で最大 ~5GB/夜）。旧既定
（総容量 20GiB / 2,000 本で古い順削除）は 104GB の SD に対して過度に保守的で、**送信待ちの
動画を黙って削除**しかねなかった。

**変更した既定値**（`video_storage.py`）:
- `WILDLIFE_VIDEO_MAX_BYTES` = **0（無効）**、`WILDLIFE_VIDEO_MAX_FILES` = **0（無効）**。
- SD 保護は「空き最低 2GiB（`WILDLIFE_MIN_FREE_BYTES`）」と「保存 14 日（`WILDLIFE_VIDEO_MAX_AGE_DAYS`）」で行う。

**優先順位**: 送信予算による遅延は最長でも約 1 時間で、保存 14 日をはるかに下回るため、通常運用
（数日の現地滞在→現地回収）では送信待ちの動画は消えない。SD が本当に逼迫したときだけ、端末保護
（録画継続）を優先して古い順に削除し、**削除は必ずログに残す（何本・何 MB・なぜ。黙って消さない）**。
必要ならバイト/本数上限は env で復活できる。

### 撮影クールダウン / サーキットブレーカー（既定 無効）

旧方針（5 分間隔・30 分 6 本で 1 時間休止）は撮り逃しを生むため撤回。コードは残すが既定で無効:
- `WILDLIFE_MOTION_COOLDOWN_SEC`（既定 **0**＝無効）。
- `WILDLIFE_BURST_PAUSE_ENABLED`（既定 **0**＝OFF。将来のバッテリー保護用の予備）。

## 見える化（`scripts/field-status.sh`）

- 送信量（直近 1 時間）/ 上限 / 残り（LTE 時）。WiFi 時は「上限なし」。
- 送信保留の本数・容量、予算切れなら再開予定時刻。
- 直近 1 時間の録画本数。
- SD 残容量と、直近ペースであと何時間もつかの概算。
