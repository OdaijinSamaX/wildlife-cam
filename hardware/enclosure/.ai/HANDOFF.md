### 2026-08-23: 箱を 84 -> 88 にした（D-022）

Pi には **CSI コネクタのラッチが壊れた個体を救うためのレスキューブラケット**
（双葉数理技術「Camera Connector Rescue」）が付いている。**Pi の外形そのものが変わる。**

**束縛していたのは「内寸 78.0」ではなく「背面の開口 74.0」だった。**
microSD を挿したままの剛体幅は **76.9 mm**（4.1 + 65.0 + 7.8。全部実測）で、
**開口 74.0 に 2.9 mm 足りない。** `rim_step` を下限 1.35 まで削っても 1.6 mm 足りず、
**幅を増やすしかなかった。** 増やした片側 2 mm は全部内側へ回してある。

**`seal` の最小圧縮率は 21.0% -> 21.2% で、落ちていない**（蓋が広くなって
断面二次モーメントが増えたぶんが、パッキン経路が伸びたぶんを上回った）。
D-019（締結 6 点）の結論は維持される。

### 2026-08-23: トレーを作り直した（D-023）

- **ブラケットが CSI 側の取付穴 2 個をねじ + ナットで占有**していた（写真で確認）。
  **共締めは不成立。** microSD 側の 2 本 + **ナットポケット 2 個**で保持する

### 2.2 「刷れば解ける」 / 「刷る前に決める」

**刷れば解ける**（刷るまで手の打ちようが無い。だから 4 と 5 を早く越える）:

- **合わせ面の反り**（計算した弾性変形 0.08 mm より大きくなりうる。**最大の未知数**）
- クリック止めの保持力（歯 0.4 mm x 45 度）
- **差し込みの感触**（片側 0.4 mm しか無い。反りが出ると入らなくなる）
- 取っ手が手袋で掴めるか / 蝶ねじが手袋で回せるか
- M2.5 タッピングの下穴 φ2.1（推定）
- 補正テーブルの暫定値・外挿（1 の `fit_coupon_v2` で潰す）

**刷る前に決める**（刷ってからでは直せない）:

- **A: FFC の曲げ**（本体の幅そのもの）
- **B: ナットの二面幅**（トレーのポケット径）
- **C: インサートの外径**（全設計の下穴）
- **D / E: リテーナと蝶ボルト**（蓋の捕捉ポケットと座ぐり）
- ドーム嵌合の溝の内径と溝の深さ（`window_snoot` を刷る前。**再測定待ち**）

## 6. 造形姿勢と「高さ 229 mm」についての注意

**混乱しやすいので明記する。**

```
PRINT_ORIENTATION = {"rotate": (90, 0, 0)}   背面の開口を上に向けて刷る
設計座標   X 88.0  Y 50.0  Z 198.0
造形姿勢後 X 88.0  Y 198.0 **Z 50.0**
```

**造形時の Z は箱の「奥行き」= 50 mm。** 設計上の高さ 198 mm は造形時には
XY 平面に寝るので、効く上限は**ベッドの 256 mm** の方である。
閉じた箱は天井ができて刷れないため、この姿勢に選択の余地はない。

「高さ 229 mm がハードな上限」という話は**設計上の高さ**についてのもので、
造形 Z の上限ではない。詳細は `docs/enclosure-body.md` §1 と D-014。

## 7. 動かし方

```bash
cd hardware/enclosure
uv sync
```

`sudo` も apt も不要。uv が Python 3.12 を取ってくる（システムの 3.14 は触らない）。

```bash
uv run python -m harness list
uv run python -m harness check designs/wildlife_cam/pcb_tray.py
uv run pytest -q
```

`out/` は生成物なので Git に入っていない。作り直すには:

```bash
for d in fit_coupon fit_coupon_v2 pir_bezel window_hood window_snoot \
         layout_study_a layout_study_b layout_study_c layout_study_d \
         camera_unit camera_unit_lid pcb_tray; do
  uv run python -m harness check designs/wildlife_cam/$d.py
done
```

**期待する結果**（2026-08-23 時点の実測。`FAIL` と `ERROR` は 1 件も出ない）:

- `out/<design>/` に STEP / STL / 3MF と PNG 9 枚と `report.md`
- `pytest`: **210 passed**（約 12 分半）
- `fit_coupon` だけ総合 **PASS**。**他の 11 設計は総合 WARN** で、その内訳は
  `overhang`（下向き面。いずれも span 10 mm 以下でブリッジ可）と
  `fit`（補正テーブルに暫定値・外挿が混じっていることの申告）だけ
- `pcb_tray` の `underside` は **PASS**（基板の下の突起 3 個すべてが受け面に当たらない）

## 8. Known risks / likely failures

1. **レンダ**: VTK の EGL オフスクリーンに依存している。GPU が見えない環境では
   例外になり、ソフトウェアラスタライザに自動で落ちる（`ENCL_RENDERER=soft` で強制可）。
   落ちたことは `report.md` の「注意」に出る。落ちても数値チェックには影響しない。
2. **起動時の警告**: `bad X server connection. DISPLAY=` が毎回出る。VTK が X を
   試して失敗し EGL に切り替える際のもので、無害。
3. **実行時間**: `check` 1 本が 20〜35 秒（テッセレーション + レイキャスト +
   ボクセル化）。`pytest` は約 12 分半。
4. **openings のボクセルピッチ**: 既定 0.5〜0.8 mm。細かくすると重くなる。
   `--pitch` で上書きできる。
5. **`cq.Face.positionAt(0.5, 0.5)` はトリムされた面の外に出ることがある**
   （実測で板の外の z が返った）。円筒面上の代表点が要るときは
   `geom.CylFace.probe_point()` を使う。
6. **`cq.Workplane.revolve` の軸はローカル座標系**。`"XZ"` ワークプレーンで
   グローバル Z 軸まわりに回すには `(0,1,0)` を渡す。ここを間違えると体積 0 の
   板ができる（manifold チェックが検出する）。

## 9. Hardware or credential gaps

- 3D プリンタ（P1S）での **実印刷は未実施**。
- **HC-SR501 は実測済み** (`measured:2026-08-22`)。ただし HOLE_DIA 2.2 と
  HOLE_PITCH 28.5 は誤差の可能性ありと申告されている（この設計は取付穴を
  使っていないので影響しない）。
- **OTG ケーブルは実測済み** (`measured:2026-08-22`)。
- IR 投光器は **実測が未実施** (`DIM_SOURCE = "estimated"`)。
- `parts/soracom_onyx.py` は外形 95x36x13 / 36g がメーカー公称 (`DIM_SOURCE = "datasheet"`)
  だが、**USB プラグ突出量・SIM スロット位置・CRC9 端子位置は推定**で、実測待ち。
  CRC9 がどちらの長辺かも不明なため、envelope は両側に逃げを取る保守的な形にしてある。
- **筐体内で最長の部品は SORACOM Onyx の 95 mm**（Pi Zero 2 W の 65 mm より長い）。
  抜き差し代を含めると 110 mm 前後の直線的な空きが要る。詳細は docs/AGENTS.md。
- スライサ連携（印刷時間・材料量の見積り）は次フェーズ。

## 10. PIR の封止方式（読まずに触らないこと）

`designs/wildlife_cam/pir_bezel.py` は名前こそベゼルだが、中身は
**接着封止キャリア**である。HC-SR501 の実測でドームに **O リングを座らせる
ツバが無い**ことが判明し（FLANGE_DIA == DOME_DIA == 23.0）、旧構成が
不成立になったため作り直した。

- 採用: 案B 接着封止（ボンドライン片側 0.30 mm / 接着代 3.3 mm / 口元に溜まり）
  + フェイス O リング（φ2.0 / 中心径 34.0）
- 不採用: 案A ラジアルシール（軸方向予算がちょうど 0、圧縮率が造形誤差で
  10〜40% に振れる、はみ出し隙間が過大）
- 不成立: 基板を使った面シール（片側 0.70 mm しか残らない）

根拠と数字は `docs/DECISIONS.md` の D-001。**造形姿勢は宣言であり、
内径の軸を造形方向に平行に保つこと**（`tests/test_checks_negative.py` が検証する）。

残リスク: フレネルドームが HDPE 系だとシリコーンは化学的に接着しない。
機械的な保持（溜まり + 狭隙間へのくさび効果）で成立させる設計にしてあるが、
実物で剥離試験をすること。

## 11. 配線レイアウトの制約

Pi Zero 2 W 65 + OTG ケーブル 150 + Onyx 95 = **310 mm** で P1S の枠 256 mm を
超える。**折り返し配置が必須。** 折り返せるのはケーブルの可動部 84.2 mm だけで、
両端のコネクタ 65.8 mm は剛体。詳細は `docs/AGENTS.md` と D-003。

## 12. 忘れてはいけない設計前提（詳細は DECISIONS.md）

- **現地で保守するのは機械に強くない人。** 設計者本人ではない（D-015）
- 設置先は **屋久島の直径 48〜64 mm の細い木**（D-016）
- **バッテリーは筐体の外**（D-017）
- **microSD は現地で抜かない**（D-018）。**だから幅 76.9 で設計している**（D-022）
- 補正テーブルは **ASA / P1S / 0.4 mm ノズル / 平置き** の組にしか意味がない（D-004）
- **ネガティブテストが無いチェックは未完成**（README / AGENTS.md）
- **パッキンを潰す合わせ面は `SEAL_SPANS` を宣言して `seal` チェックを通す**（D-019）
- **現地で外すねじは `CAPTIVE_SCREWS` を宣言して `captive` チェックを通す**（D-020）
- **基板を載せる設計は `UNDER_BOARD` を宣言して `underside` チェックを通す**（D-023）
- **蓋の柱 6 点は内部レイアウトを強く縛る**（D-021）。ただし
  **天井から吊れば柱の間を使える**（D-023）
- **x の余裕は片側 0.4 mm しか無い**（D-022 / D-023）。**内部に何かを足すときは
  必ず `docs/pcb-tray.md` §2 の収支を見ること**

## 13. Smallest acceptable fix policy

- チェックの閾値を緩めて PASS にするのは禁止。形を直すか、設計の docstring に
  理由を書いて `CHECK_CONFIG` で明示的に上書きする。
- 新しい失敗を潰したら `tests/test_checks_negative.py` にその失敗を再現する
  ケースを足す。ネガティブテストの無いチェックは未完成とみなす。
- `parts/` の推定寸法を触るときは `DIM_SOURCE` を必ず更新し、その部品を使う
  全設計で `harness check` を回し直す。
