# 基板トレー — CSI レスキューを付けた Pi を、幅 88 の箱に入れる

- 日付: 2026-08-23（**2 度目の作り直し**。1 度目は同日の D-021）
- 対象: `designs/wildlife_cam/pcb_tray.py` / `camera_unit.py` / `camera_unit_lid.py`
- 部品: **`parts/pi_zero_2w_rescue.py`（新規）**
- 決定: `docs/DECISIONS.md` **D-022**（箱を 88 へ）/ **D-023**（保持方式と受け）

## 0. 結論

**Pi の外形が変わったので、箱ごと引き直した。**

CSI コネクタのラッチが壊れた個体を救うレスキューブラケットを付けると、
Pi は「幅 65 mm・裏はほぼ面一・取付穴 4 個」ではなくなる。

| | 裸の Pi | **レスキュー装着後** | 出所 |
|---|---|---|---|
| 剛体幅（microSD 込み） | 69.1 | **76.9** | 実測 2026-08-23 |
| 基板下面より下 | 0.4 | **2.7** | 実測 2026-08-23 |
| トレーが使える取付穴 | 4 | **2** | 写真で確認 2026-08-23 |
| 平面にべた置き | できる | **できない** | 上から計算 |

| | 値 |
|---|---|
| 箱の外形 | **88.0** x 50.0 x 198.0 mm（**84 -> 88**。D-022） |
| 背面の開口 | **78.5**（74.0 -> 78.5。`rim_step` 2.0 -> 1.75） |
| トレーの外形 | 77.7 x 41.7 x 10.5 mm（造形姿勢後） |
| Pi の保持 | **microSD 側の M2.5 x 2 本 + ナットポケット 2 個** |
| トレーの保持 | 棚（-Z）/ **天井から吊ったフック**（+Z）/ リップ（±X）/ 当たり（-Y）/ クリック（+Y） |
| ポカヨケ | **フックの段 0.8 mm**（前後反転）+ **取っ手**（上下・左右+上下） |

## 1. 束縛していたのは「内寸 78.0」ではなく「背面の開口 74.0」だった

**ここが今回いちばん効いた検算である。**

トレーは背面から引き出す（D-021）。つまり **Pi を載せたトレーは、背面の合わせ面の
開口を通らなければならない。** その開口は側壁の内寸より狭い。

```
側壁の内面      x ±39.0     内寸 78.0
合わせ面の land x 37.0〜42.0（rim_step 2.0 のぶん内側へ張り出す）
**背面の開口**  **x ±37.0** -> **74.0**
```

一方、**microSD を挿したままの剛体幅は 76.9 mm。**

```
microSD の突出   4.1   実測 2026-08-22（D-018: 現地では抜かない）
Pi Zero 2 W     65.0   datasheet
レスキューの張出  7.8   実測 2026-08-23
------------------------
                76.9   ->  開口 74.0 に **2.9 mm 足りない**
                        ->  内寸 78.0 には入る（1.1 mm）
```

**「内寸には入るが、開口を通らない」**という状態だった。
内寸だけを見ていると成立しているように見えるので、ここは必ず開口で見ること。

### 1.1 `rim_step` を削っても足りない

`rim_step` の下限は **1.35 mm** である。蓋のパッキン溝（幅 2.70）は本体の land の
上に丸ごと乗っていなければならず、溝の内側の縁は `側壁の内面 - 1.35` に来るからだ
（`tests/test_camera_unit.py::test_body_land_carries_the_whole_gasket_groove` が
毎回実測している）。

```
rim_step 1.35 のときの開口 = 75.3   ->  まだ 1.6 mm 足りない
```

**だから幅を増やすしかなかった。** 決定と不採用案は D-022。

---

## 2. x の収支（**もう 1 mm も余っていない**）

幅 88 / `rim_step` 1.75 で、片側の予算はこうなる。

```
壁の内面        41.00
位置決めリップ  39.25   （リップの厚み 1.75）
**背面の開口**  39.25
トレーの板      38.85   開口まで 0.40
Pi + microSD    38.45   板の縁まで 0.40 / リップまで 0.80
```

**すべての隙間が 0.40 mm。** これがこの設計のいちばん張り詰めている所で、
**ここに何かを足す余地は無い。**

この収支から出てくる結論が 2 つある。

1. **側壁から内側へ棚を出す C チャンネル（D-021）はもう成立しない。**
   棚を Pi の外（x >= 38.85）へ下げると 2.15 mm のひさしになり、掛かり代が取れない
2. **+Z の押さえは x を使えない。** だから**天井から吊った**（§3）

### 2.1 剛体の中心 ≠ 基板の中心

microSD が -X に 4.1 mm 出ているので、**剛体（カード + 基板 + ブラケット）の中心を
開口の中心に合わせる**と、基板の中心は x = **-1.85** に来る。
基板中心で合わせるとカード側が 2 mm はみ出して通らない
（`test_the_rescue_pi_is_centred_on_the_opening_not_on_the_board`）。

---

## 3. +Z の押さえを天井から吊る（D-023 の要点）

側壁から内側へ出せないなら、**上から降ろせばよい。**

```
        z
       195  ┌─ 天井の内面
            │  フック（x ±18〜25。**柱の間**）
       181  ├──┴──  下面 181.4 (+X) / 180.6 (-X)  <- ポカヨケの段 0.8
       180.8 ───────  トレーの縁の上端（+X 側）
            │
       179.7 ───────  Pi の上端
            │
       149.7 ───────  Pi の下端
       149.2 ───────  トレーの下端 = 棚の天面
       147.0 ═══════  棚（x ±34.5〜41）
       146.1 ─ 柱の影の下端
```

**副産物が大きい。** 棚とフックが側壁から離れたことで、**受けの z が蓋の柱に
縛られなくなった。** D-021 では柱の影（z 146.1〜181.3 の 35.2 mm）に
棚・Pi・押さえを全部詰め込む必要があり、Pi の 30 mm を置くと余りが 5.2 mm しか
なかった。いまはフックが柱の外（|x| <= 25）にいるので、その制約が消えている。

---

## 4. Pi の保持 — 残る自由度は 1 つだけだった

**ブラケットは CSI 側の取付穴 2 個を「ねじ + ナット」で占有している**
（上から ねじ頭 -> 耳 -> 基板 -> **ナット 2.0** -> ねじ先 0.7。写真で確認）。
だから**共締めは物理的に不可能**で、トレーが使えるのは microSD 側の 2 穴だけ。

ねじ 2 本で **面内（x, z, 面内回転）は完全に決まる。**
残るのは **2 本を結ぶ線まわりの回転** = CSI 端が ±Y に振れる、の 1 自由度だけ。

これを **ナットポケット 2 個**（φ6.6 x 深さ 3.4）で止める。

- ナットが **2.7 mm 落ち込む**ので、CSI 端は ±x / ±z に位置決めされる
- +Y も 2.7 mm ぶん拘束される。**最後を止めるのは蓋**
  （D-021 でトレー自身の +Y を蓋が止めているのと同じ考え方）
- ポケットの位置は **Pi の機構図の値**（各辺から 3.5 / ピッチ 23.0）で決まるので、
  **`RESCUE_Y_POS` が未実測のままでも引ける**

### 4.1 「測らなくて済む設計」を優先した

`RESCUE_BOT_H = 2.7` は**定盤に伏せて置いて測った最深部**なので、
**アセンブリ全体の下限**でもある。だから受け側が 2.7 + 0.4 を空けさえすれば、
**基板の外に張り出したバーの下がり量を測らなくてよい。**

同じ理由で、**バーをトレー側の溝で掴む案は採らなかった**
（バーの寸法を 1 つも測っていない）。
現地 UX としては溝の方が良いが、推定で彫れば外れたときに作り直しになる。

## 5. 13 個目のチェック `underside` を足した

**12 種のどれも「実装部品が基板の下に出ている」ことを捕まえなかった。**

`clearance` は部品の envelope と筐体の積を見るが、**基板を受ける座面には
envelope を太らせない**という規約がある（`docs/AGENTS.md` §4）。基板はボスの天面に
**接するのが正しい**からで、太らせると正しい設計が FAIL になる。
**その免除が、基板の下にぶら下がっているものを丸ごと飲み込む。**

`UNDER_BOARD` を宣言すると、**`build()` した形状にレイを格子状に飛ばして**
「基板下面から下に空いている隙間」を実測し、`突出量 + クリアランス` と比べる。
意味・閾値・限界は `docs/HARNESS.md` の 12。

**ネガティブテスト 3 本**（`tests/test_checks_negative.py`）:

- 座面を 2.0 mm に縮める -> 2.7 mm のナットが当たって **FAIL**
- ポケットを塞ぐ -> 受け面が基板下面と同じ高さに来る -> **隙間 0 で FAIL**
  （実装当初、レイの交点を `depth > 0` で拾っていたせいで、この面が除外されて
  「5.9 mm 空いている」という嘘の値が出ていた。**その回帰テストでもある**）
- 座面を 0.5 mm 伸ばすと実測値もちょうど 0.5 mm 増える（**形から測っている**証拠）

## 6. 実機で確かめること（計算では出せない）

1. **FFC の曲げ半径。★いちばん怪しい**
   FFC はバーの上を通り、基板上面とほぼ同じ高さで **水平に +X へ出る**（x = 38.45。
   `FFC_EXIT = "horizontal"` は写真で確定）。そこから前面のカメラ（z=60）へ向かうには
   90 度曲げる必要があるが、**半径 3.0 mm を取ると外側が x 41.75 に達し、側壁の
   内面 41.0 を 0.75 mm 超える。** 使える手は 3 つ:
   - 静的曲げなので半径 2.55（厚みの 8.5 倍）で通す。**一般の下限 10 倍を割る**
   - 側壁のその z 帯（12 mm ほど）だけ外へ 1.5 mm 膨らませる
     （**y < 44 のみ。リムは 88 のまま = パッキン経路に触らない**）
   - 幅を 88 -> 89.5 にする
   **トレーの形はどの手を採っても変わらない**ので、ここでは止めていない。
2. **ナットの二面幅**（`NUT_AF` は推定 5.0）。ポケット φ6.6 が決まる
3. **クリック止めの保持力**（歯 0.4 mm x 45 度）。蓋を開けて箱を傾けて落ちないこと
4. **差し込みの感触**。**片側 0.4 mm しか無い**ので、反りが出ると入らなくなる。
   **合わせ面の反りの実測（`docs/lid-fastening.md` §6）はここにも効く**
5. **M2.5 の下穴 φ2.1**（推定）
6. **取っ手が手袋で掴めるか**（リップが +Y へ 8 mm。板の上端 z 180.8〜190）

## 7. D-021 から引き継いだもの / 捨てたもの

| | D-021 | **D-023** |
|---|---|---|
| 差し込み方向 | +Y -> -Y（背面から） | **同じ** |
| +Y の最後の止め | 蓋 | **同じ** |
| -Z の受け | 側壁からの棚（x ±34.5〜39） | 側壁からの棚（x ±34.5〜**41**） |
| **+Z の押さえ** | 側壁からの押さえ | **天井から吊ったフック**（x ±18〜25） |
| **ポカヨケ** | -X 側の棚だけ 2.5 mm 高い | **フックの段 0.8 mm** + **取っ手** |
| **取っ手** | x 33.3〜36.0 のタブ 2 枚 | **板の上端（|x| <= 15・z 180.8〜190）** |
| Pi の保持 | M2.5 x **4 本** | **M2.5 x 2 本 + ナットポケット 2 個** |

**ポカヨケは対照実験で役割分担が分かった。**
段違いが**単独で**効いているのは**前後反転だけ**で、上下反転と「左右+上下」反転は
**取っ手が単独で止めている**（取っ手は板の上端にしかないので、z を反転すると
下端へ来て棚に当たる）。**両方をテストにしてある**ので、どちらかを触った瞬間に
どちらが効かなくなるかが分かる。
