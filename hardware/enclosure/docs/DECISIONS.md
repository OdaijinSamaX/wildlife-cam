## D-001: HC-SR501 を筐体壁に防水で貫通させる方式

- 日付: 2026-08-22
- 状態: **採用 = 案B（接着封止キャリア）**
- 実装: `designs/wildlife_cam/pir_bezel.py`
- 前提: `parts/hcsr501.py` (`DIM_SOURCE = "measured:2026-08-22"`)

### 経緯

初版の `pir_bezel.py` は「ドームのフランジ（ツバ）を O リングで筐体壁に
押し付けて密封する」構成だった。これは推定寸法（フランジ φ24.6 / ドーム φ23.0）に
基づいていた。

2026-08-22 の実測で **FLANGE_DIA == DOME_DIA == 23.0 mm**、指でなぞっても段差が
無いことを確認した。**ツバは存在しない。** 旧構成は物理的に成立しない。

実測値（ノギス）:

| 項目 | 値 |
|---|---|
| PCB_L / PCB_W / PCB_T | 32.8 / 24.4 / 1.4 mm |
| DOME_DIA | 23.0 mm |
| DOME_H | 14.4 mm（基板表面から頂点） |
| SKIRT_H | 3.3 mm（ドーム根元の円筒部） |
| BACK_COMP_H | 8.0 mm（導出: 23.8 - 14.4 - 1.4） |
| モジュール全高 | 23.8 mm |
| HOLE_DIA / HOLE_PITCH | 2.2 / 28.5 mm（**誤差の可能性あり**） |

### 案X: 基板を使った面シール — **不成立**

基板の前面（ドームの外周に残る平坦部）に O リングを当てる案。

```
使える幅 = (PCB_W - DOME_DIA) / 2 = (24.4 - 23.0) / 2 = 0.70 mm
```

溝を切るには「溝幅 + 両側の land（各 min_wall = 1.6）」が要る:

| コード径 | 溝幅 (1.35 x cord) | 必要幅 | 判定 |
|---|---|---|---|
| φ2.0 | 2.70 | 5.90 mm | 不成立 |
| φ1.5 | 2.03 | 5.23 mm | 不成立 |
| φ1.0 | 1.35 | 4.55 mm | 不成立 |

**入手できる最小のコード径でも 0.70 mm には収まらない。** 検討終了。

### 案A: φ23.0 の円筒スカートにラジアルシール — **不採用**

O リング溝は PIR 側に切れないので筐体（キャリア）側の穴に切る。
使えるシール長は SKIRT_H の **3.3 mm しかない**。

φ1.0 コード / 圧縮率 25% で設計すると:

```
半径すきま = 1.0 x 0.75 = 0.750 mm
溝底径     = 23.0 + 2 x 0.750 = 24.50 mm
溝幅       = 1.0 x 1.35 = 1.35 mm
内径       = 23.0 + 2 x 0.15 = 23.30 mm
```

**不採用の理由は 3 つ。いずれも単独で不採用に足りる。**

1. **軸方向の予算がゼロ。**

   ```
   面取り 0.50 + 溝 1.35 + land 1.45 = 3.30 mm  =  SKIRT_H 3.3 mm
   ```

   余裕が 0.00 mm。しかも PIR の軸方向位置は「印刷した座面に基板が当たる
   位置」で決まり、ドームキャップが基板に完全に着座しているかどうかも
   個体差がある。±0.5 mm も動けば O リングがスカートを外れて球冠（曲面）に
   乗る。乗った瞬間に漏れる。

2. **圧縮率が造形誤差で潰れる。** P1S で φ23 の内径を刷ったときの実力を
   ±0.15 mm とすると:

   | 造形誤差 | 圧縮率の振れ |
   |---|---|
   | ±0.10 mm | 15% 〜 35% |
   | ±0.15 mm | **10% 〜 40%** |
   | ±0.20 mm | 5% 〜 45% |

   静的シールの下限は 15% 前後。10% では封止できない。40% では圧縮永久
   ひずみが出る。**φ1.0 という細いコードを使う以上、絶対量が小さすぎて
   造形誤差を吸収できない。**

3. **はみ出し隙間が大きすぎる。** 内径 - ドームの片側すきまは公称 0.15 mm。
   内径が 0.2 mm 大きく出れば 0.35 mm になり、φ1.0 コードに対して 35%。
   低圧でもはみ出しの領域に入るうえ、ドームががたついてシール面が動く。

なお造形姿勢については、**内径の軸を造形方向に平行**にすれば
積層線はシール面を縦断しない（同心の閉じたリングになる）。この点だけは
案A でも解決できたので、採用案でも同じ姿勢を宣言している。

### 案B: 接着封止キャリア — **採用**

PIR を印刷したキャリアにシーラントで封止・固定し、キャリア側に好きな形状の
フランジを作って筐体と面シールする。

```
内径 φ23.6（ドーム φ23.0 に対し片側 0.30 mm のボンドライン）
接着代 スカート全長 3.3 mm
口元に φ25.6 x 深さ 1.2 mm のシーラント溜まり
フェイス O リング φ2.0 コード / 中心径 34.0 / 溝 2.70 x 1.50
```

**採用の理由:**

1. **公差に鈍い。** 0.30 mm はボンドラインであって圧縮量ではない。
   造形誤差 ±0.2 mm はボンドライン 0.10 〜 0.50 mm の変動になるだけで、
   どれもシーラントとして成立する範囲。案A の「10% 〜 40%」とは性質が違う。
2. **狭い 3.3 mm に精度を要求しない。** 軸方向位置が多少ずれても、
   接着代が減るだけで機能が切り替わったりしない。
3. **本命のシール（フェイス O リング）を好きな寸法で設計できる。**
   中心径 34.0 / φ2.0 コードなら、造形誤差 ±0.15 mm でも圧縮率は
   20% 〜 30% に収まる。

**失うもの:** PIR を交換できない。

  → キャリアは印刷部品なので刷り直せる。HC-SR501 自体も安価。
    「交換 = キャリアごと作り直し」で済むので、失うものは小さい。
    屋外で浸水すれば装置ごと死ぬことと比べれば、明らかに割に合う。

**残っているリスク（要検証）:** フレネルドームの材質。PIR 用フレネルレンズは
HDPE 系のことが多く、**シリコーンは HDPE に化学的に接着しない**。
そこでこの設計は接着力に頼らず、**機械的な保持**で成立するようにしてある:

  - 口元の溜まり（φ25.6 x 1.2）に硬化したシーラントの環ができる
  - その内側は 0.30 mm の狭隙間に連続している
  - **外圧はシーラントを狭隙間へ押し込む向きに働く**（くさび効果）。
    抜け出す向きには効かない

それでも実物で剥離試験をすること。剥がれるようなら、ブチル系または
ポリウレタン系のシーラントに変える。

### 造形姿勢（両案に共通、採用案で宣言済み）

`PRINT_ORIENTATION = {"rotate": (180, 0, 0)}` — **内径の軸は造形方向 (Z) に平行**。

  - 軸を寝かせると内径の積層線が軸方向に走り、シール面／接着面を縦断する
    連続した溝ができる。ラジアル方向の漏れ経路そのもの。内径も垂れて
    真円でなくなる。
  - 軸を立てれば内径は同心の閉じたリングの積み重ねになり、層境界は軸に
    直交する面になる。
  - 180 度反転しているのは、フェイス O リング溝の**シール面をビルドプレート側**に
    持ってくるため。第 1 層は最も平坦で密な面になる。

この姿勢は `tests/test_parts.py` で機械的に検証している。

### 派生する制約（筐体本体設計への申し送り）

- 筐体壁の穴は φ26.0。キャリアは壁の**内側**から当てる。
- 取付ねじ M3 x 4 は筐体内側から通し、**壁の外側に張り出した肉厚パッド**の
  ヒートセットインサートに締める（壁 3.0 mm ではインサートの 6 mm が入らない）。
  **インサート穴は止まり穴にすること。**
- ねじはフェイス O リングの外側（乾燥側）に置く。

## D-002: LTE モデムの形態

- 日付: 2026-08-22
- 状態: 確定
- 実装: `parts/soracom_onyx.py`

`parts/eg25g.py` は mini-PCIe カード（30 x 51 x 4.5）と仮定していたが、実物は
**SORACOM Onyx LTE USB Modem (SC-QGLC4-C1)** = USB-A 直付けドングルで、
外形は 95 x 36 x 13 mm だった。中の無線モジュールが Quectel EG25-G。
u.FL x 2 という想定も誤りで、実際は外部アンテナ端子 CRC9 x 2（MAIN / DIV）。

CRC9 端子が長辺のどちら側にあるかが未確定なので、envelope では**両側**に
27 mm ずつ逃げを取っている。実測が入れば片側に落とせる。

## D-004: 造形の寸法誤差をどこで吸収するか

- 日付: 2026-08-22
- 状態: 採用
- 実装: `harness/fit.py` / `harness/checks/fit.py`
- 根拠データ: `designs/wildlife_cam/fit_coupon.md`

### 経緯

fit_coupon v1 を P1S / ASA / 0.4 mm ノズル / 平置きで印刷して実測したところ、
**穴は 0.25 〜 0.30 mm 小さく、外形の突起は 0.25 mm 小さく出た。壁は誤差ゼロ。**
この癖を設計に反映する必要が出た。

### 検討した案

**案1: 設計スクリプトの中で足し引きする（不採用）**

```python
"shaft_dia": 10.1 + 0.30,     # 補正
```

不採用の理由:

- 補正値が全設計に散らばる。材料を変えたときに追えない。
- `PARAMS` の値が「狙い」なのか「図面」なのか読んで分からなくなる。
- チェックが補正後の形を測ってしまう。`clearance` は「補正で膨らんだ穴」に対して
  クリアランスを判定することになり、実物と違う数字を出す。

**案2: 出来上がった形状を後処理でオフセットする（不採用）**

穴だけを外側に、外形だけを内側に、というオフセットは B-rep の一括処理では
書けない。穴と外形を機械的に判別できない。

**案3: テーブルを持ち、`build()` を 2 回評価する（採用）**

設計は狙い寸法だけを書き、`FIT_TABLE.hole()` / `.boss()` / `.wall()` を通す。
ハーネスが同じ `build()` を 2 通りに評価する。

| モード | `hole(10.1)` | 使い道 |
|---|---|---|
| `target` | 10.1 | **全チェックとレンダ**（印刷後の形を検証する） |
| `print` | 10.4 | **STL / 3MF**（スライサに渡す） |

これで:

- 設計にマジックナンバーが入らない
- 補正値は 1 箇所（テーブル）にあり、材料ごとに差し替えられる
- **チェックは「印刷後にこうなるはずの形」を測る。** `clearance` の 0.25 mm も
  `wall` の 1.6 mm も、実物に対する数字として意味を持つ
- `expected_openings` などの宣言も狙い寸法のまま書ける

コスト: `build()` が 2 回走る（クーポンで 2 〜 4 秒）。許容範囲。

### テーブルの素性を必ず持たせる

補正値は **材料・機種・ノズル径・層厚・造形姿勢** の組にしか意味がない。
`FitTable` はこれらを必須フィールドとして持ち、`fit` チェックが毎回レポートに
出す。別材料に移るときの手順は `fit_coupon.md` の 5 章。

### 「無補正」を 2 種類に分ける

- `FIT_TABLE = fit.NONE` — **意図して補正しない**（v1 クーポンがこれ）
- `FIT_TABLE` 未宣言 — **測り忘れ / 考え忘れ** -> `fit` チェックが FAIL

黙って素通りさせないために、この 2 つを区別している。
個々の寸法についても `f.uncompensated(値, "理由")` があり、report に
「無補正」として記録される。

## D-005: fit_coupon v1 の基準ピンが台座と一体だった

- 日付: 2026-08-22
- 状態: v2 で修正
- 実装: `designs/wildlife_cam/fit_coupon_v2.py`

**設計ミス。** v1 では基準ピン φ10.0 が台座と一体で生えていたため、
**同じ板の軸穴 φ10.1 〜 10.4 に挿して嵌合を確かめることが物理的にできなかった。**
クーポンの目的の半分（軸穴嵌合の確定）が達成できていない。

v2 の対処: ピンを台座から独立させ、台座を貫く φ18.0 のソケット穴の中に立てて、
底の細いタブ 2 本（1.5 x 0.8 mm・合計断面 2.4 mm2）だけで繋ぐ。

- タブは第 1 層側（z = 0 〜 0.8）にしか無いので、測定に使う高さ（z = 2 〜 14）に
  折り跡が残らない
- ピンはビルドプレートに直接立つので、下向きの張り出しが出ない
- ピンの軸は軸穴と同じく造形方向に平行。**同じ向きで刷ったもの同士**を
  嵌合させるので比較に意味がある
- タブ高さ 0.8 mm は薄板の最小値と同値。クーポンの `min_wall_mm` 0.8 を
  下回らないので `wall` チェックが通る

**v1 のファイルは凍結する。** 実際に刷って測った実物の記録であり、
書き換えると補正テーブルの根拠が失われるため。

## D-006: 外部アンテナ (CRC9) は使わない

- 日付: 2026-08-22
- 状態: 確定
- 実装: `parts/soracom_onyx.py`（`envelope()` の既定を `external_antenna=False` に）

SORACOM Onyx の外部アンテナ端子 CRC9 x 2 は使わない。**ドングル単体で通信できることを
実機で確認済み。** したがって:

- **筐体の貫通が 2 つ減る**（漏水の第一原因なので効果が大きい）
- envelope から片側 27 mm の逃げが消え、幅が 91 mm から 37 mm になった

**代わりに配置ルールが要る。** 内蔵アンテナ 1 本になるので:

- **Onyx は筐体の壁際に置く**
- **金属および他の基板を近づけない**

`designs/wildlife_cam/_layout_common.py` の `antenna_metrics()` がこれを数値で見る
（アンテナ端 - 壁 6 mm 以下 / 他基板 10 mm 以上）。3 案とも満たしている。
離隔 10 mm は経験則で、実測の裏付けは無い。

## D-007: 箱の中を貫く剛体の実長は 115.0 mm

- 日付: 2026-08-22
- 状態: 確定
- 実装: `parts/soracom_onyx.ASSEMBLED_WITH_OTG_L`

Onyx 単体（実測 89.4 mm）ではなく、**OTG ケーブルの USB-A メスを挿した組立状態の
115.0 mm** が、箱の中を貫く曲がらない実長。レイアウトを支配するのはこちら。

```
実測  BODY_L 77.5 + PLUG_L 11.9 = 89.4     （旧公称 95 とは 5.6 mm 食い違う。実測を採る）
組立  89.4 + USB-A ハウジング 35.0 - 差し込み代 9.4 = 115.0
```

差し込み代 9.4 mm はプラグ長 11.9 mm より短く、辻褄が合う（テストで検証）。

後端 20.8 mm は厚みが 13.2 から **9.3 に落ちる面取り**があり、その脇には他の部品を
寄せられる。面取りが片側だけか両側対称かは測っていない（`THIN_IS_SYMMETRIC` は推定）。

## D-009: カメラ窓は既製品のドーム蓋（案S）

- 日付: 2026-08-22 / 状態: 採用
- 実装: `parts/dome_lid.py` / `designs/wildlife_cam/window_snoot.py`
- 詳細: `docs/window-options.md`

視野の計算が「対角 76 度では **真っ直ぐな筒は L < 1.281 r** でしか成立せず、
短くて末広がりの形にしかならない」と言った。**現行機が使っていた透明な
食品用カップの形とそのまま一致した。計算が実物を説明した。**

したがって作り直すべきは光学ではなく**耐久性**。PET は紫外線で数ヶ月で白濁し、
瞬間接着剤は温度変化と振動で微細に割れる。同じ形を耐候材と弾性シールで作り直す。

窓は既製品のドーム蓋（口径 76.0 / 深さ 32.2 / **頂点の平窓 φ25.0** / 肉厚 0.4）。
**レンズは平窓から 16.0 mm 以内**でなければ四隅が欠ける（フランジ位置では
半角 21.2 度）。前壁から筒を伸ばしてカメラを送り出す。`fov` チェックが検証する。

**不採用: 平板 + 庇（案H）。** 実績が無く、雨粒はドームの曲面の方が自然に流れる。
ドームの入手が途切れたときの代替として `window_hood.py` に残す。

## D-010: 視野チェック（fov）をハーネスの一般機能として新設

- 日付: 2026-08-22 / 状態: 採用
- 実装: `harness/fov.py` / `harness/checks/fov.py`

設計が `VIEW_CONES` を宣言すると、**印刷される部品と内蔵部品の両方**を円錐と
ブーリアン積して食い込みを実測する。食い込み量は体積と**角度**（円錐の半角から
何度内側まで入っているか）で出す。

レンズ諸元（焦点距離 4.74 / センサ対角 7.4）は**要検証**なのでパラメータ化した。
円錐の頂点は既定でセンサ面に置く（入射瞳の位置が不明なため、円錐が最も太くなる
＝保守側に倒す）。ドーム設計だけは用途に合わせてレンズ前面を頂点にしている。

**限界:** 透明な窓材は「遮っている」と判定される（透過は見ていない）ので、
窓そのものを COMPONENTS に入れてはいけない。

## D-011: 現地で保守する人のための設計原則

- 日付: 2026-08-22 / 状態: 採用（**全設計・全プロジェクトに適用**）
- 実装: `docs/AGENTS.md` §4.9 / `docs/field-procedure.md`

**現地で保守するのは機械に強くない人**で、設計者本人ではない。
落とした部品は落ち葉の中で見つからない。

原則: 捕捉式のねじ / 大きく少なく / ポカヨケ / パッキンの座りが見える /
刻印で現地に情報を残す / 工具なしを優先。

**制約:** 防水にはパッキンを潰す力が要るので締結力は弱くできない。
**印刷したスナップ爪では面圧が足りない。** 力が要る所は**蝶ねじかトグルラッチ**。

box-trap-sensor など他プロジェクトでも同じ性質の現場があるので、
`docs/AGENTS.md` に一般原則として書いた。

## D-012: スライド嵌合を優先する。ただし摺動シールはピストン式だけ

- 日付: 2026-08-22 / 状態: 採用
- 実装: `docs/AGENTS.md` §4.9.3 / §4.9.4 / `designs/wildlife_cam/fit_coupon_v2.py`

固定はできるだけねじではなくスライド嵌合にする。ただし:

- **スライドだけでは振動で抜ける。** 位置決めはスライド、**抜け止めは別に最小限**。
- **摺動面の造形方向**を `PRINT_ORIENTATION` で宣言する。
- **丸穴で取った補正値（穴 +0.30 / 突起 +0.25）は角形状に効く保証が無い。**
  `fit_coupon_v2` に隙間 +0.2 / +0.3 / +0.4 / +0.5 のアリ溝試験を追加した。
  レールは受けと別部品で、台座を貫く抜き穴の中に立てて折り取りタブで繋ぐ
  （v1 の「基準ピンが挿せなかった」失敗を繰り返さないため）。

**摺動シールの線引き:**

| 形 | 成立 | 理由 |
|---|---|---|
| ピストン式（半径方向） | **する** | O リングが半径方向に潰れる。摺動距離が短い。`pir_bezel` の横展開 |
| 引き出し式（面を擦る） | **しない** | パッキンが摺動して摩耗し、溝から転がり出る。数回で漏れる |

**パッキンを潰す合わせ面はスライドで代替できない。** ねじかラッチが要る。

ベイパースムージング（アセトン）は摺動シール面の品質を上げるが、**寸法が変わる
ので補正テーブルの再校正が要る**。引火性が高く容器は PP 製。
**いまは採用しない。摺動シールを採る場合の選択肢として記録するだけ。**

## D-013: 取り付け評価のやり直し -> 推奨を 案A から **案D** へ

- 日付: 2026-08-22 / 状態: 採用
- 実装: `designs/wildlife_cam/layout_study_d.py`
- 詳細: `docs/layout-study.md` §5

現地写真で**幹の直径が 48〜64 mm** と判明した。§3 の「幹径 150 mm 以下なら案C」は
桁を外していた。

**背面の鞍（V 溝 44 x 16）が必須要件**になった。平面を直径 50 mm の丸い幹に
当てても線接触にしかならず、ベルトで締めても回転する。ベルト溝（幅 30 mm・2 本）
も鞍の中に彫る。

案A〜C は幅 118〜138 mm で、幹に対して片側 35〜45 mm 張り出す（ねじりのてこ）。
**幅を最小化した案D**（77.0 x 50.7 x 229.0）を追加した。

| | 案A（旧推奨） | **案D（新推奨）** |
|---|---|---|
| 幹からの横張り出し 片側 | 44.9 mm | **14.5 mm** |
| 受風面積 / 鞍の接触長 | 137.8 mm | **77.0 mm** |
| 総質量の目安 | **150.6 g** | 166.8 g |
| 体積 | **794.8 cm3** | 894.0 cm3 |

細い木では**風のねじりが支配的**なので、張り出しと接触長を優先する。
質量と体積の +11〜12% は許容する。

**残る懸念:** 高さ 229 mm は P1S の 256 枠に対して余裕 27 mm しかない。
リブやボスを足すと造形できなくなる危険がある。本設計に入る前に確認すること。

## D-014: カメラユニット本体の実設計

> **2026-08-23 改訂: 外形幅は 84 -> 88 になった。理由と経緯は D-022。**
> 高さ 198 / 奥行き 50 / 造形時の Z 50 は変わらない。

- 日付: 2026-08-23 / 状態: 採用
- 実装: `designs/wildlife_cam/camera_unit.py` / `camera_unit_lid.py`
- 詳細: `docs/enclosure-body.md`

### 高さ 229 mm は造形の上限として効いていなかった

背面の開口を上にして刷るので、**造形時の Z は箱の「奥行き」= 50 mm**。
設計上の高さ 198 mm は XY 平面に寝るので、効く上限はベッドの 256 mm。
閉じた箱は天井ができて刷れないため、この姿勢に選択の余地はない。

**それでも高さは 229 -> 198 mm に減らした**（受風面積 -13%）。造形のためではなく
取り付けのため。余裕は安全のためにある。

### 幅は 77 -> 84 mm。ドームの口径が決めた

嵌合リブ（外径 79.4）が 77 mm には入らない。**幹からの張り出しは
片側 14.5 -> 18.0 mm（+3.5、+24%）。** これがドームを使う限りの下限。
高さを減らしたぶん受風面積は差し引き -6%。

### 蓋は蝶ねじ 4 本（M4 x3 + M5 x1）

パッキン周長 760 mm を潰すのに合計 2.3〜3.8 kN、4 点で 1 点 570〜950 N が要る。
**印刷したスナップ爪では桁が足りない。** トグルラッチは力は足りるが側面に付ける
必要があり、幅が増えて案D を選んだ理由を壊す。蝶ねじは内部の柱に締めるので
幅に影響しない。**1 本だけ M5 + 位置を 1 mm ずらしてポカヨケ**にしてある。

### 一体造形を推す（分割の判断材料は docs に）

造形 Z は 50 mm、footprint 84 x 198 も枠内なので、**分割する造形上の理由が無い**。
分割すると周長 270 mm の合わせ面が増え、これは貫通を 1 つ増やすより悪い可能性がある。
分割が要るとすれば、実機で反りが出たときで、そのときは上下ではなく**前後**に割る。

### 貫通 4 つ。通気つきグランドで 3 に減らせる

PG7 の把持範囲 3.0〜6.5 に対し、素のケーブル 2.8 は**下限を下回る**ので
テープ増径は必須。増径後 5.0 は範囲の中央で締め代が最も安定する。
通気機能つきグランドが入手できれば貫通が 3 に減る。**入手性を先に確認すること。**

## D-016: 設置先は屋久島の直径 48〜64 mm の細い木

- 日付: 2026-08-22（幹径）/ 2026-08-23（場所を明記）/ 状態: 確定
- 実装への反映: `camera_unit_lid.py` の鞍 / `docs/layout-study.md` §5

**設置場所は屋久島。** 取り付ける木の幹は**円周 15〜20 cm、すなわち直径 48〜64 mm。**
細く、しなる。

ここから出る制約:

- **平らな背面では線接触にしかならない。** V 溝の鞍（半角 54 度 / 幅 44 / 深さ 16）が
  必須要件。直径 48〜64 の範囲で 2 線接触になる
- **重量と受風面積が想定より強く効く。** 幹から遠い位置の質量ほど揺れる
- **横張り出しがねじりのてこになる。** レイアウトの推奨が案A から案D に変わった原因
- 若い木なので**ベルトが成長を締め付ける**。幅の広いベルト・緩衝材・年 1 回の
  付け替え・釘を打たない（`docs/field-procedure.md` §D）

屋久島は年間降水量が非常に多く高湿である。**防水の要求水準はこの前提で読むこと**
（具体的な等級は未決定）。

## D-019: 蓋の締結は 4 点では足りない。中央に 1 対足して 6 点にする

- 日付: 2026-08-23 / 状態: 採用
- 実装: `camera_unit.PARAMS["lid_bosses"]` / `harness/seal.py` / `harness/checks/seal.py`
- 詳細: **`docs/lid-fastening.md`**（式・仮定・比較した案・感度）

### 経緯

人間から「長辺 198 mm を四隅 4 本で押さえて、辺の中央でパッキンの面圧が足りるのか」
という指摘が出た。D-014 の時点では**たわみ計算をしていなかった**（未検証と書いてあった）。

蓋を梁、パッキンを非線形の弾性床とみなして解いた結果:

| | 四隅 4 点 | **6 点（採用）** |
|---|---|---|
| 締結点 z | 12 / 186 | **12 / 142 / 186** |
| 中央の浮き | 0.233 mm | **0.080 mm** |
| 最小圧縮率 | **13.3%**（下限 15% 割れ） | **21.0%** |

**指摘は正しかった。** ただし前回の一次見積り 0.85 mm は 3.7 倍の過大評価で、
断面二次モーメント（レール 2 本しか数えていない）・線圧（出所なしの 4 N/mm）・
「浮いても線圧は一定」という仮定の 3 つが重なっていた。**訂正は
`docs/lid-fastening.md` §3 に表で残してある。**

### なぜ「締結点を増やす」なのか

たわみは**支間の 4 乗**で効く。ほかの手段は桁が足りないか制約に触る。

- **剛性で直すには EI が 4.2 倍要る**＝蓋の断面高さ 22 -> 36 mm。
  幹から 14 mm 遠ざかり、案D（張り出しを減らす）を自分で壊す
- 外面のリブは**鞍の V の中＝幹の当たり面**なので置けない
- コード径を上げても「浮き / 予算」の比は変わらない（荷重も予算も径に比例する）。
  しかも溝幅 4.05 mm は本体の land 5 mm に入らない
- 金属の補強材と CF フィラメントは**内蔵アンテナの近くに導体**を置くので D-006 に反する
- 柔らかいゴム（50 Shore A）は単独では足りない（17.4%）が、6 点と併せると余裕が増える

### 失うもの

**ねじが 4 -> 6 本に増える。** 現地 UX 原則 2「小さいねじ 8 本より大きいねじ 3 本」と
逆行する。**面圧の要求（防水）を優先した。** 原則 2 自身が
「締結点が減るぶん 1 点あたりの面圧は上がるので、パッキンの潰し量は再計算すること」
と書いており、再計算した結果が「4 点では足りない」だった。

### 副次的に決まったこと

- **上のベルト溝を z 148.5 -> 164.3 に動かした。** 蓋は幹に巻いたベルトで
  押さえられているので、**ベルトの下に来た蝶ねじは現地で回せない。**
  テストで固定してある（`test_belts_do_not_cover_the_thumbscrews_or_the_labels`）
- **刻印 1〜6 は側面に彫る。** 鞍の面には座ぐりとの間に 1.6 mm の肉が残らない
- ポカヨケが 2 重になった。M5 が 1 本 + **中央の対が上下非対称**なので、
  180 度回すと穴の位置自体が合わない
- **背面リムの不具合が見つかった。** 「パッキンが何に当たっているのか」を実形状で
  測ったら、押し出し量に切り抜き用の「+1」が入っていて **land だけが背面より
  1 mm 飛び出し、合わせ面の幅が 5 mm から 2 mm に痩せていた。**
  蓋の溝はその段差の縁に跨がっており、外側半分は空中だった。
  **どのチェックにも掛からない種類の不具合**（穴でもソリッド干渉でも薄肉でもない）
  なので、再発防止のテストを足した（`test_body_land_carries_the_whole_gasket_groove`）

### 検討したが不採用: 中央の対を z=99 に移す

**中央の対を長辺の真ん中 z=99 に置ければ 24.4% になり、実効弾性率の推定に
ほとんど依存しなくなる。** そこには Onyx がいて、どかすには x 方向に 10 mm
内側へ寄せる必要があり、**D-006「Onyx は壁際に置く」に触る。**

**2026-08-23、人間が「Onyx は動かさない」と決定した。中央の対は z=142 で確定。**
21.0% は目標 20% を満たしており、レイアウトは D-008 / D-013 で比較検討して
決めた結果なので、面圧のために崩さない。**蒸し返さないこと。**
再燃しうるのは実機で合わせ面の反りが大きかったときだけで、そのときも
z=99 より先に反りそのものを潰す方を検討する。詳細は `docs/lid-fastening.md` §7。

### この件でハーネスに足したもの

`wall` は「薄いこと」しか見ず、**長い蓋がたわんでパッキンが浮く**失敗は
どのチェックにも掛からなかった（HARNESS.md の限界に明記してあった通り）。
`seal` チェックを新設し、`SEAL_SPANS` を宣言した設計では毎回この計算が回る。
**断面二次モーメントは `build()` した形状から実測する**ので、形を触れば数字が動く。

## D-020: 蝶ねじの捕捉は「蓋の内側のポケット + 軸に付けた平たいリテーナ」

- 日付: 2026-08-23 / 状態: 採用
- 実装: `camera_unit_lid.PARAMS["retainer_*"]` / `harness/captive.py` / `harness/checks/captive.py`
- 詳細: **`docs/captive-fasteners.md`**（寸法の連鎖・比較した案・不採用の理由）
- 出所: `docs/field-procedure.md` C-3 の宿題（未設計だった 6 本ぶん）

### 決めたこと

蓋のシール面側に **捕捉ポケット φ9.8 / φ11.8 x 深さ 10.5** を彫り、
**蝶ボルト M4 x 30（1 本だけ M5 x 30）** の軸に平たいリテーナを 1 個付ける。
リテーナは **E 形止め輪（JIS B 2805）呼び 4 / 呼び 5**、または
**外径 9.3 mm 以下の押しナット（プッシュナット）** のどちらでもよい。

**蓋の形はどちらでも同じ。** ポケット径は両方を受けられるように決めてある。
**リテーナの選択は調達の問題であって設計の問題ではない**、という形にした
（部品の型番が確定していないうちに設計を止めないため）。

| | 値 |
|---|---|
| ねじが後退できる量 `travel` | **9.7 mm**（ポケット 10.5 − リテーナ厚 0.8） |
| 噛み合い `engage` | **8.0 mm**（呼び径の 2 倍） |
| 緩めきったときの出しろ | **1.3 mm** < 柱までの隙間 3.0 mm |
| **最小圧縮率（`seal`）** | **21.0%（ポケットを彫る前と同じ）** |

### 効いた制約は「止め方の確実さ」ではなく「パッキン溝までの距離」だった

締結点 x = ±31 とパッキン溝の内縁 x = 37.65 の間に min_wall 1.6 を残すと、
**ポケット径の上限は φ10.1、リテーナ外径の上限は φ9.3** になる。
市販の平型スピードナット（M4 で外径 14 前後）はこの時点で落ちる。
締結点の x は D-019 で決まっているので動かさない。

M5 の 1 本は**ポカヨケで x = -30 に 1 mm 寄せてある**ぶん上限が φ12.1 まで緩み、
E 形 呼び 5（外径 11.0）が入った。**ポカヨケのためのずらしがたまたま効いた。**

### 不採用（理由の要点。詳細は `docs/captive-fasteners.md` §6）

- **ばね + キャプティブナット**: 9.7 mm 動くばねを置ける場所が無い（座ぐりは 3 mm）。
  柱との隙間に入れると**パッキンの面圧と喧嘩する**
- **首に O リング / ねじ込みナット + ねじロック**: 緩めるたびにリテーナがねじ山を
  **先端側へ歩いて**いずれ抜ける。**止め輪と押しナットはねじ山に噛んでいないので
  空回りするだけで移動しない。ここが形式の分かれ目**
- **印刷したスナップ爪**: ねじ山が爪を切って抜ける。ASA は屋外でクリープする
- **蓋側にもインサート**: 回せば必ず抜ける。**原理的に捕捉ではない**
- **本体側に植込みボルト + 蝶ナット**: 蓋が自動で芯出しされる利点はあるが、
  **落とす部品が蝶ナットに変わるだけ**で要件を満たさない
- **既製のキャプティブスクリュー（PEM PF 等）**: 蝶頭が無く工具が要る / 入手性

### 本体を 1 箇所直した

M4 x 30 はインサート（深さ 8）を使い切るので、下穴がインサートと同じ深さだと
**先端が下穴の底を突いて、締めたつもりで面圧が出ない。**
`lid_pilot_depth`（= 12.0）を新設し、インサート 8 + 先端の逃げ 4 にした。
**2026-08-25 に 14.0 へ改めた**（M5 インサートの実測全長 10.0 が支配する。D-024）。

### この件でハーネスに足したもの

`captive` チェック（**12 個目**）。捕捉は**寸法の連鎖**でしか成立せず、
連鎖が切れると「ねじが落ちる」「蓋が開かない」「下穴の底を突く」
「蓋を平らに置けない」のどれかになる。**どれも `wall` / `openings` / `layout` /
`seal` は見ていないし、現地に行くまで気づけない。**
ポケットの深さと座面の深さは**申告させず、`build()` にレイを飛ばして実測する。**
ネガティブテストは 4 本（`tests/test_checks_negative.py`）。

## D-021: 基板トレーは z 方向のスライドではなく「背面から差し込む」

> **2026-08-23 改訂: 保持方式と受けは D-023 で作り直した。** 差し込みの方向
> （背面から）と「+Y の最後は蓋が止める」は引き継いでいるが、**棚・押さえ・
> ポカヨケ・取っ手・ねじの本数は全部変わっている。** 幅も 84 -> 88（D-022）。
> **以下の数字は D-021 時点のもの**（背面の開口 x ±37 など）。現行は D-023。

- 日付: 2026-08-23 / 状態: **D-023 で改訂**
- 実装: `designs/wildlife_cam/pcb_tray.py`（新規）/ `camera_unit.PARAMS["tray_*"]`
- 詳細: **`docs/pcb-tray.md`**（数字・比較した案・不採用の理由）
- 出所: `docs/enclosure-body.md` §9 の未設計 1 番

### 決めたこと

本体に作ってあった **z 方向のアリ溝レール（z 128〜194）は撤去した。**
代わりに、蓋の柱の影のない窓（z 146.1〜181.3）に
**背面（開口側）から差し込む C チャンネル**を作り、トレーを落とし込む。

  - -Z（自重）… 棚 / +Z … 上の押さえ（遊び 1.2 mm）
  - ±X … 位置決めリップ（片側 0.4 mm）/ -Y … 前の当たり
  - **+Y（抜け）… クリック止めの歯**（蓋を開けているとき）/ **蓋**（閉めているとき）

### なぜアリ溝が成立しないのか（**D-019 の後始末**）

**理由は 2 つあり、どちらも「レールを短くする」では解けない。**

1. **柱が Pi の通り道を塞ぐ。** 蓋の柱が x 26.9〜35.1 を占めるので内側に残る幅は
   53.8 mm。**Pi Zero 2 W は 65 mm あるので柱の z を通り抜けられない。**
   アリ溝は端から差し込むしかないので、この時点で不成立。
   柱の影のない窓は 35.2 mm しかなく、Pi の丈 30 mm を置くと動かせるのは 5.2 mm。
2. **背面の開口は x ±37 しかない**（合わせ面の land が 2 mm 内側へ張り出すため）。
   **側壁のアリ溝に届く幅のトレーは、そもそも開口を通れない。**

つまり **D-019（締結 6 点）がアリ溝方式を殺した。** 指示にあった
「柱を避けた形にする」を素直にやると、方式そのものが落ちる、という結果である。

### ポカヨケ（原則 3）

**-X 側の棚だけ 2.5 mm 高く、トレーの -X 側の下隅はそのぶん欠けている。**
左右・前後・上下のどの反転でも、低い方の棚に欠けていない縁が乗って 2.5 mm 浮き、
上の押さえに当たる。**3 通りの反転を実際に回転させ、z を ±6 mm 総当たりして
必ず当たること**をテストにした。さらに**対照実験**（段違いを消すと座ってしまう）も
入れてあり、ポカヨケの根拠がどこにあるかを機械が知っている。

### 不採用（詳細は `docs/pcb-tray.md` §4）

- **アリ溝を柱の間だけに短くする**: 端が無いので乗せる方法が無い
- **アリ溝 + 落とし込みの窓（キーホール）**: 窓 + 掛かり代 + 行程が 35.2 mm に入らない
- **トレーに柱の逃げスリットを開ける**: スリットが全長に要るので板が分断される
- **Pi を縦置きにして幅を 30 mm にする**: 案D（D-008 / D-013）の再検討になる
- **前壁から柱を立てて支える**: 成立するが、棚を内側へ伸ばすだけで足りた
- **ねじ 1 本で留める**: 現地で工具が要る（原則 6）

### ついでに直した不具合

**旧レールは宣言 z 128〜194 に対し、実物が z 62〜128 だった。**
`cq.Workplane("YX")` の法線が -Z なので、extrude が逆向きに伸びていた。
**どのチェックにも掛からない**（穴でもソリッド干渉でも薄肉でもなく、Onyx とも
x で 1 mm すれ違っていた）。`docs/lid-fastening.md` §8.1 の背面リムと同じ種類の
**「宣言と実物がずれる」失敗**である。
作り直した受けには、**ビルド結果から z を測って宣言と突き合わせる**テストを足した。

## D-023: Pi の保持は「microSD 側の 2 本 + ナットポケット」。トレーの受けも作り直した

- 日付: 2026-08-23 / 状態: 採用
- 実装: `designs/wildlife_cam/pcb_tray.py`（全面書き直し）/ `camera_unit._tray_receiver`
- 詳細: `docs/pcb-tray.md` / 部品は `parts/pi_zero_2w_rescue.py`
- **D-021 を改訂する**（差し込みの方向と「蓋が +Y を止める」考え方は引き継ぐ）

### 決めたこと 1: ねじは microSD 側の 2 本だけ

実測（2026-08-23・写真 2 枚で確認）で、**レスキューブラケットは Pi の CSI 側の
取付穴 2 個を「ねじ + ナット」で占有している**ことが分かった（上から
ねじ頭 -> 耳 -> 基板 -> **ナット 2.0** -> ねじ先 0.7、合計で基板下面から **2.7 mm**）。

**共締め（トレーのボスをナットの代わりにする）は不成立。** ねじの裏はナットで
塞がっていて、トレー側から同じ穴を使う道が無い。

残る自由度は **2 本のねじを結ぶ線まわりの回転**（CSI 端が ±Y に振れる）だけ。
これを **ナットポケット 2 個**（φ6.6・深さ 3.4）で止める。ナットが 2.7 mm
落ち込むので、CSI 端は ±x / ±z に位置決めされ、+Y にも 2.7 mm ぶん拘束される。
最後を止めるのは蓋（D-021 でトレー自身の +Y を蓋が止めているのと同じ考え方）。

### 決めたこと 2: +Z の押さえを「天井から吊る」

**x の予算がもう無い**（開口 39.25 / 板 38.85 / Pi 38.45。片側 0.4 mm ずつ）。
側壁から内側へ出す C チャンネル（D-021）は、**その x を Pi 自身が占めてしまう。**

  - 棚を Pi の外（x >= 38.85）へ下げると、棚が 2.15 mm のひさしになり、
    トレーが載る掛かり代が取れない
  - **+Z の押さえだけを天井から吊れば、x は柱の間（|x| <= 25）で足りる**
  - 副産物: **棚とフックの z が柱に縛られなくなった**

### 決めたこと 3: ポカヨケを棚からフックへ移す

D-021 は **-X 側の棚だけ 2.5 mm 高く**していたが、**そこにはもう Pi の下端が来る。**
段を「天井から吊ったフック」に移した（**-X 側だけ 0.8 mm 低い**）。
Pi の上端（178.5）より上なので干渉しない。0.8 なのは、下げた側のフックが
「0.6 mm 持ち上げた Pi の上端」に当たらない上限だから。

**対照実験で分かったこと**: 段違いが**単独で**効いているのは**前後反転だけ**で、
上下反転と「左右+上下」反転は**取っ手が単独で止めている**（取っ手は板の上端に
しかないので、z を反転すると下端へ来て棚に当たる）。両方をテストにしてある。

### 決めたこと 4: 取っ手を板の上端へ移す

D-021 の掴みタブ（x 33.3〜36.0）は、**幅 76.9 の Pi の真下になって置けない。**
板の上端（z 180.8〜190・|x| <= 15）へ移した。ここは柱の間で、本体のフック
（|x| 18〜25）にも当たらない。リップが +Y へ 8 mm 出るので、手袋のまま指が掛かる。

### 決めたこと 5: 「測らなくて済む設計」を優先する

`RESCUE_BOT_H = 2.7` は**定盤に伏せて置いて測った最深部**なので、
**アセンブリ全体の下限**でもある。だから受け側は 2.7 + 0.4 を空ければ、
**基板の外に張り出したバーの下がり量を測らなくてよい。**

### 不採用

| 案 | なぜ落ちたか |
|---|---|
| **共締め**（トレーのボス -> 基板 -> ブラケットの耳を 1 本で貫く） | **ねじの裏はナット。** 物理的に不可能（2026-08-23 の写真で確定） |
| **ブラケットの外側のバーをトレー側の溝で captive にする** | 現地 UX としては一番良いが、**バーの寸法を 1 つも測っていない**。推定で溝を彫ると、外れれば作り直しになる。**「測らなくて済む設計にする」方を採った** |
| **基板の縁をリップで押さえる** | 基板の上面は CSI 端から 28.8 mm ぶんブラケットが覆っていて、リップを掛ける縁が片側 0.6 mm しか残らない |
| **側壁から内側へ出す C チャンネルのまま x を詰める** | 棚の掛かり代 か Pi の幅 のどちらかが必ず負けする（上の「決めたこと 2」） |
| **棚に段を付けたままポカヨケを維持** | 段の位置に Pi の下端が来る。段を 0 にすると前後反転が座る（対照実験で確認） |

## D-025: ドームの締め代は直径 0.2 mm。**保持はボルトが担うので「割れない」を優先する**

2026-08-25 の断面実測で、ドーム蓋に**抜け止めビードが無い**ことが分かった（⑤）。
対になるカップが無いので締め代（⑦）は測れない。**設計側で決めてよい**（人間の了承済み）。

### まず役割分担を訂正した

`parts/dome_lid.py` の旧記述「**保持は既製品の嵌合に任せる**」は、
ビードが無いという実測と矛盾する。ひっかかりが無い以上、嵌合の保持力は当てにできない。

| | 旧（誤り） | 新 |
|---|---|---|
| 保持 | 既製品の嵌合 | **取付ボルト 3 本**（非等分角のポカヨケ） |
| 位置決め | 嵌合 | 嵌合 |
| 防水 | 下に敷く O リング | 同じ |

**これが締め代の決め方を変える。** 抜けない強さは要らず、
**割れない範囲で位置が出れば足りる。**

### 数値の根拠: PET のフープひずみを 0.3% 以下に抑える

締め代 δ（直径差）をドームが受けると、縁のフープひずみは概ね `ε = δ / D`。

```
D = 76.9（溝の内径・暫定）
ε <= 0.3%  ->  δ <= 0.003 x 76.9 = 0.23 mm
```

PET の降伏ひずみは 2〜3% あるが、**0.3% で切った**理由は 3 つ。

1. **薄肉の成形品で、縁は折り返し（④ 0.9 ≒ 0.4 x 2）**。応力集中が読めない
2. **紫外線で白濁して脆化する**（`docs/window-options.md`）。**新品で保つ設計では足りず、
   寿命末期のドームで割れないこと**が要る
3. **現地で交換する**（§4.9 原則: 機械に強くない人が、手袋で）。
   力を要る嵌合は現地作業として不適

したがって **δ = 0.2 mm（半径 0.1 mm）** を設計値に置く。

### 緩む側に転んでもよい（**そこが効いている**）

印刷側の補正テーブルは φ8 以上で +0.30、公差は ±0.2 級。
**実際には締め代が消えて隙間になることがある。** それでも

- **保持はボルト 3 本**なので落ちない
- **防水は下の O リング**なので漏れない

**「緩い側の失敗は無害、きつい側の失敗はドームが割れる」という非対称**があるので、
**小さい方に倒すのが正しい。** これは D-024 の下穴（迷ったら小さい方）と同じ判断軸である。
